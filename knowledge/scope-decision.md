# 自動化プロジェクトの撤退判定基準

**3回同じ障壁で失敗したら、スコープ縮小の判定フェーズへ移行する。**

## 判定軸（順序重要）

1. **技術実現可能性** — 実装パターンが存在しないなら即断念。本番でしかテストできないなら適性「低」。
2. **ビジネスROI** — 月次利用量 × 削減時間 > 初期実装 + 保守コスト か？
   - BOOTH：月3-5件 × 3分 = 月15分 < 月5時間保守 → 【赤・スコープ縮小】
   - note：月10+件 × 5分 = 月50分 > 月1時間保守 → 【緑・継続】
3. **仕様透明性** — 仕様不明確 ＋ テスト環境なし なら本番デバッグ地獄。即座に手動へ。

## 判定時機

- セッション1-2：実装できるかの検証フェーズ
- セッション3以降：ROI判定フェーズ
- 同じ障壁で3回失敗 → 即座に「赤・スコープ縮小」

## スコープ縮小の選択肢

- A. **ハイブリッド**（推奨）：AI生成 + 人間の最終操作 + 自動リマインダー
- B. **全手動**：AI生成まで自動化し、あとはユーザーに委ねる
- C. **完全放棄**：時間ROIが完全に負のときのみ

ハイブリッドを選ぶ基準：初期実装5h < 完全自動化30h（既投資）+ 月5h保守、かつ 月手動0.5h << 月5h保守 → 転換で月4.3時間削減。

## 実例（BOOTH自動出品）

```
[S9]  新規出品URL検出        → ✅
[S10] URL検出ロジック改善     → ✅
[S11] 商品作成ページ到達      → ✅（ここまでOK、ROI算出フェーズへ）
[S12] 商品入力+PDF+出品      → ❌ サイレント失敗【1回目】
[S13] PDF再実装+出品再試      → ❌ サイレント失敗【2・3回目】
      → 判定「赤」でハイブリッドへ転換すべきだった
```
