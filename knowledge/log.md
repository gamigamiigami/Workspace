### [2026-09-23] ポケット秘書 第2弾 — オンライン秘書アプリ（PWA＋Cloudflare）に作り直し

**プロジェクト：** ポケット秘書 (`projects/pocket-hisho/`)

**なぜ作り直したか**
伊神さんから要件が追加された：「予定を登録すると**自動で通知**」「**タスク一覧**」「情報の一元化」
「スマホメイン＋**パソコンからもアクセス**」「**Googleカレンダーと同期**」
「App Storeの有料アカウントもMacBookも無いが、スマホアプリとして通知を出したい」。

前回のオフライン版（HTML1枚・端末内保存・通信ゼロ）とは**両立しない**ことを先に伝えた。
とくに前回 README に「ホーム画面に追加してもSafariタブとして開く作りにした」と書いた点は、
**今回は真逆**になる（iPhoneはホーム画面から全画面で起動したときだけ通知を許可できるため）。
画面の設計（日/週/月/年・1件＝1カード）は引き継ぎ、裏側を作り直すことで合意。

**技術選定（選択肢を数えたら1つに絞られた）**

| 選択肢 | 判定 | 理由 |
|---|---|---|
| ネイティブ（Swift/Kotlin） | ❌ | iPhoneに入れるには Mac(Xcode)＋Apple Developer Program（年約1.5万円） |
| React Native / Flutter | ❌ | 結局 iPhone に配るところで同じ壁 |
| **PWA** | ✅ | App Store不要・Mac不要・無料。iPhone/Android/PCが1つのコードで動く |

サーバーは **Cloudflare Workers + D1 + Cron Triggers**（すべて無料枠・クレカ不要）。
通知は **Web Push（VAPID署名＋aes128gcm暗号化）を自前実装**。
カレンダーは OAuth を避け、**ICSの二方向**（購読用URLを配る／シークレットアドレスを取り込む）で
認証ゼロのまま実質双方向にした（未審査のOAuthは7日でトークンが切れ、渡した相手の手元で壊れるため）。

**作ったもの**
- `src/` Worker（受け口・ログイン・保存・1分ごとの見回り・ICS入出力）
- `web/` PWA本体（Service Worker でオフライン表示と通知受け取り）
- `web/shared-date.js` `web/shared-model.js` … **サーバーと画面が同じファイルを読む**（時差とデータ形の二重定義を防ぐ）
- `SETUP.md` … Cloudflare のセットアップ手順（**ブラウザだけで完結**する道筋。Node不要）
- `tools/make-icons.mjs` … PNGアイコンを外部ライブラリ無しで生成

**検証：Playwright／Node で 344項目すべて合格**（本体80・通知判定61・サーバー108・画面95）。
JSエラー0。**どの順番で流しても同じ結果**になるところまで直した。
- 暗号化した通知を**偽の通知サーバーへ実際に送り、端末の鍵で復号して中身を確認**。
  他人の鍵では読めないこと、VAPID署名が公開鍵で検証できることも確認
- **本番と同じ経路（Cron → 通知）**で届くこと、二度目は送られないこと
- 外部カレンダーの取り込み（繰り返し展開・向こうで消えた予定の反映・不通URL）
- 電波を切った状態での起動・入力・復帰時の送信
- 月末/うるう年/年またぎ、同日2件、120文字の会場名、`<img onerror>` のエスケープ
- タップ領域44px以上・横スクロールなし（390/768/1280px）・明暗ともコントラスト4.5以上
- スクリーンショット15枚を目視確認

**テストで見つけて直した不具合（5件）**

| 見つけたこと | 原因と直し方 |
|---|---|
| **オフラインで開き直すと真っ白**（`ERR_FAILED`） | `/index.html` はサーバーが `/` へ転送するため、取っておいた応答に「転送された」印が付く。**転送された応答は画面をひらく要求には使えない決まり**。`/` を取っておき、さらに応答を作り直すようにした。`clone()` では直らない |
| 時刻未定の予定で**同じ通知が2回**届く | 「2時間前」と「30分前」がどちらも当日8時に潰れていた。時刻の無い予定は「何日前か」で重複を除き、1日1回にした |
| オフラインで**起動**すると「つながっていません」の帯が出ない | 「値が変わったときだけ描く」最適化が、起動時＝すでにその値のときに一度も描かないことになっていた |
| 取り込みをやめたカレンダーの予定が**消えずに残る** | 「設定にあるぶんだけ消して入れ直す」作りで、設定から消えたものが処理対象外だった |
| 入力画面のチェックが指に小さい（24px） | 44pxの `<label>` で包んだ。設定のオン/オフ行も `<label>` にして行ごと押せるようにした |

**切り分けで効いたやり方：** オフラインの真っ白は「テスト環境のせい」で片づけかけたが、
**SWの処理を『その場で作った応答を返すだけ』に一時的に差しかえる実験**をしたところ表示できた。
これで「ナビゲーションはSWに届いている＝自分の分岐が原因」と確定し、原因の範囲が一気に狭まった。

**knowledge 追記：** failures.md 5件、patterns.md 5件、ui-components.md 2件。索引は再生成済み。

  つまずいたら画面のエラー文字をそのまま持ってきてもらう

### [2026-09-22] ポケット秘書 — 新規作成（セミナー講師むけ 予定・お金の手帳）

**プロジェクト：** ポケット秘書 (`projects/pocket-hisho/index.html`)

**何を作ったか**

**決まった仕様**
- 使う人：その講師の方だけ（伊神さんは作って渡す側）
- 端末：スマホ中心。扱うのは 開催予定・会場／移動・宿泊／売上・経費／主催者・連絡先
- **背骨＝「1つのセミナー＝1枚のカード。当日は開くだけで全部わかる」**
- 追加要望で **日・週・月・年の4段ビュー**（「年間・月間で詳細は要らない」）
  → **見る範囲が広いほど情報を減らす**を設計ルールにした。どこをタップしても「日」に着地する
- 通信ゼロ・外部CDNなし・完全無料。データは端末内（localStorage）のみ
- 必須入力は**日付だけ**（入力が面倒なツールは使われなくなるため）

**途中で見つけて直したもの（自分のテスト・スクリーンショットから）**

| 見つけたこと | 直し方 |
|---|---|
| 入力画面が390px幅で**114pxはみ出す** | `<fieldset>` だけ既定が `min-inline-size: min-content` だった。`min-inline-size:0` を付与 |

| ダークモードで**＋ボタン・選択タブ・印の文字が読めない**（コントラスト比 2.08／基準4.5） | 背景だけ変数化して文字を `#fff` 直書きしていた。`--on-navy` を新設し8か所を置換（→ 8.82） |
| 時刻の入力欄が「**12:3C**」で切れる | 3等分だと約100px、`input[type=time]` には130px要る。`flex: 1 1 130px` で折り返しに |
| 月の一覧で**日付と会場名がくっつく／金額が＋ボタンに隠れる** | 日付欄を78pxに広げ、金額を右端から2行目へ移した |
| うるう日 2028-02-29 の翌年が**3/1になる** | `addYears` を `addMonths(s, n*12)` に統一（月末そろえの処理を共有） |
| 月カレンダーの土日に色がない | `.cal-cell.sat / .sun` を追加（週ビューと同じ `--sat` `--sun` 変数を使用） |
