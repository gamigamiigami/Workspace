### [2026-09-10 ②] セッション200 — 迷路謎メーカー 手で赤にもどした線けし段が作れない／組み上げ優先

**指摘**（3段：あおもじだけ→あおいせんをけせ→みどりだけ、3段めを②で赤に、20×20・少なめ・わき道なし）
> こんな設定でもだめになってる。ルート短すぎとか、制限多すぎとかだよ。迷路をくみ上げることを優先してくれ

**原因（数えて確定）**
- 同じ色の段どうしは「自分だけが通るマス」にしか文字を置けない。線を消す区間は最長7マスだったので
  自分だけのマスは最大9。5文字を離して置くには14要る → `place:2` で全滅（4/8・2.5秒、画面では0）。
- さらに `earlierRoutesKept(i)` が「読み直しでつながった前の段」まで見ていたため、
  「読み直す→線を消す」の並びでは遠回り作り（forceDetour）が**必ず**落ちて受け皿の近道さがしに流れていた
  （受け皿は自分だけのマスを増やせない）。

**直したこと**
- `forceDetour(…, fresh)`：次の段と同じ色の段があるときは、区間＝`spreadNeed(次の文字数)`、
  まわり道＝`spreadNeed(前の同色の文字数)` の長さで掘る。長いまわり道は輪っかが増えて最短が1本に
  ならないので、`G.rewireAsTree(work, 長い道, [], 残す辺)` で木の形に組み直してから確かめる（generate.js に公開・`keepEdges` 追加）。
- `earlierRoutesKept(upto, skipPath)`：同じ道を読む段は飛ばす。
- `stageNeeds(st, texts, sc)`：同色をまたぐ線けしは次の段の `spreadNeed` を道の長さに上乗せ。
- `build()`：もう広げられない大きさでは 60回・道は必要な長さの10割増しまで（前は30回・6割）。
- `forceDetour` の探索回数に上限（80）。無いと作れない組み合わせで1分近く待たせた。
- `checkRecipe`：線けし直後の線けしで次の段を手で同色にした形だけは作れない（実測 0/2・30秒）ので、選んだ時点で理由と直し方を出す。
- wizard の色の説明に「②で赤にもどすこともできる」を追記。README に実測表。

**実測（同じ乱数の種）**
- 伊神さんの例：4/8・2.5秒 → **8/8・0.1秒**（わき道ありでも 8/8・0.2秒）。12/8/12文字 20×20 でも 4/4・0.6秒。
- 既定の8組み合わせ：4/8〜8/8 → **すべて 8/8**（0.5〜3.6秒）。
- 作れない入力（読み直し6段×12文字 20×20）の待ち時間：約13秒。

**検証**：node 8本＋ブラウザ 8本 pass。新テスト `samered1.js`（画面で3段めを赤にして自動作成→成功）。

**次のアクション**：iPad実機テスト待ち（3段めを赤にして作ったときの見た目：消す前と後で通る道が大きく違うか、赤い文字が両方の道にまたがっていないか）。

### [2026-09-09 ②] セッション199 — 迷路謎メーカー 線を消す段でも赤にもどせるようにする

**指摘**
> せんをけすも、もともとのルートと全然違うルートを通ることができれば同じ色の文字でもいいはず。
> もし同じ文字が含まれるなら、元のルートと交差したり合流すればいいが、そうではないならルートごと変える。
> そのための遠回りさせる設定です？

**そのとおりでした。しかも、前の私の説明がまちがっていました。**

きのう「線を消す段では赤にもどせない（構造的に無理）」と報告したが、
理屈だけで判断していた。実際に同じ色のまま作らせたら、ふつうの長さの文章でも **3/6** 作れた。
原因は、下限として設けた値（線を消すと最低3マスは道が変わる）を
「3マスしか変わらない」と読みちがえていたこと。

**どこまで道を分けられるかを実測した**

| 前後それぞれで「自分だけが通るマス」 | 作れる率 | 時間 |
|---|---|---|
| 3マス（線を消す1回ぶん） | 8/8 | 0.2〜0.6秒 |
| 7〜8マス | 8/8 | 2.1〜3.2秒 |
| 11〜12マス | 5/8 | 5〜10秒 |
| 14マス | 1〜5/8 | 9〜12.5秒 |

そのうえで、実際に同じ色にして通しで作らせた：

- 赤 → 赤（線を消す**1回**）… **2/8**
- 赤 → 青 → 赤（線を消す**2回**）… **7〜8/8**

**「1回では足りない／2回なら足りる」**という線が数字で引けたので、
`ERASE_TO_REUSE = 2` にした。

**新しいきまり**

```
色でしぼる → 線を消す → 線を消す
　　あか　→　あお　→　あか（2回はさんだので、もどせる）

色でしぼる → 線を消す
　　あか　→　あお（1回では道がにすぎるので、もどせない）
```

STARTやGOALが変わる段は道がまるごと別物になるので、**1回で赤にもどせる**（これまでどおり）。
同じ色を使えるのは2段まで（3段で急に作れなくなる）。
「線を消す」段どうしの線の色は、これまでどおり ぜったいに使い回さない。

**色の並びがこう変わった**

| 組み合わせ | 前（公開中） | 新 |
|---|---|---|
| 3段 線けし2回 | 赤 青 黄 | 赤 青 **赤** |
| 4段 読み直し＋線けし2回 | 赤 青 黄 緑 | 赤 青 黄 **赤** |
| 5段 色絞り2＋線けし2（伊神さんの例） | 赤 青 黄 緑 紫 | 赤 青 黄 緑 **赤** |

**ついでに直った：文章が短い謎で、遠回りを作る余地が無くなっていた**

赤にもどすと作りにくくなった原因を数えたら `stage:erase-wall`（遠回りを作れない）が最多だった。
道をのばして作り直すしくみは「置き場所が足りない」ときだけ働く形にしてあったが、
**遠回りを作れないときも道が長ければ解ける**（文章が短い謎は道も短くなり、余地が無い）。
`roomShort` に `stage:erase-wall` を足したら **2/16 → 10/16**、
伊神さんの5段の例は **9/16 → 15/16** になった。

**作れる率と時間（公開中 → 新・同じ乱数の種で8回ずつ）**

| 組み合わせ | 公開中 | 新 |
|---|---|---|
| 3段 線けし2回 | 8/8 0.6秒 | 7/8 3.9秒（赤がもどる） |
| 4段 読み直し＋線けし2回（既定の文章） | 8/8 0.9秒 | 7/8 2.7秒（赤がもどる） |
| 4段 読み直し＋線けし2回（自作の短い文章） | 8/8 0.6秒 | 4/8 3.5秒（赤がもどる） |

| 5段 色絞り2＋線けし2（伊神さんの例） | 8/8 0.7秒 | 8/8 1.7秒（赤がもどる） |

赤にもどす形は、色を散らす形より**作りにくく・遅い**（8/8・0.6秒 → 4〜8/8・1〜4秒）。
それでも「赤＝場面が切りかわった」が伝わるほうを既定にした。

### [2026-09-09] セッション198 — 迷路謎メーカー 段の色のルールを元にもどす／道の遠回りをおさえる

**指摘への対応（2点）**

| 指摘 | 対応 |
|---|---|
| 色絞り→色絞り→せんけし→色絞り→せんけし で作ったら**毎回読む色が変わった**。もともと伝えてあったと思うけど、色を絞って読むを使ったら次の色、線を消したりスタゴル変えたら**赤に戻す**んだよ | **私がきのう勝手に変えていた。**元のルールにもどした。そのままでは謎が成り立たない場合だけ例外にし、**なぜずらしたかを②の画面に出す**ようにした |
| 5段でも作れるようになったが、**かなり遠回り**になっている。もう少し短くするか、文字数が少ないときは短いルートにしてほしい | 道の長さに上限を入れた。上限は「いまの長さ」ではなく「**いま まっすぐ帰ったら何マスになるか**」で見る。道をのばして作り直すのも、**のばして効く行きづまりのときだけ**にした |

**① 色のルールは、私が変えてはいけないものだった**

きのう「4段が作れない」を直したとき、原因が段の色の割りあてだと分かった。
そこで「まだ使っていない色を優先する」に変えたのだが、
**この割りあては伊神さんが設計として決めたもの**だった（赤にもどす＝ここで場面が切りかわった）。
コードのコメントを読んで「見た目の都合でしかない」と自分で判断し、確認せずに置きかえていた。
報告でも「原因は自分が決めた既定値でした」と書いたが、決めたのは伊神さんだった。

**元のルールにもどした：**

| しかけ | 次の段の色 |
|---|---|
| 色でしぼって読み直す | **次の色へ進む**（赤→青→黄→緑→紫） |
| 線を消す／STARTが変わる／GOALが変わる／STARTもGOALも変わる | **赤にもどす** |

**そのうえで、謎が成り立たない場合だけ例外にする：**

1. 「線を消す」段どうしが同じ色 → 別の色（紙の指示は色なので、ほかの段の線まで消える）
2. **赤にもどした先に、道がほとんど同じ前の赤い段がある** → 次の色へずらす
3. 同じ色の段が3つになる → 3つめから次の色へ（3つで急に作れなくなる。実測 3/12・42秒 → 2段までなら 12/12・4秒）

**2 の説明（伊神さんの例がここに当たる）：** 段の色は「文字が何色か」だけでなく
**「その段の文字を置けない場所」**も決めている。同じ色の段が2つあると、片方を読むときに
もう片方の文字までいっしょに読めてしまうので、おたがいの道をよけて置く必要がある。
STARTやGOALが変わる段は前の道と重ならない道を選ぶので赤にもどせるが、
**「線を消す」段は前の道をほとんどそのまま通る**ので、赤にもどすと置き場所が消える。

ずらしたときは②の画面に理由を出すようにした（黙ってずらすと「勝手に変わっている」に見える）。

> ※ 3段め・5段め は**赤にもどせません**でした。線を消しても道はほとんど同じままなので、
> 前の赤い段と同じ色にすると、その段を読むときに前の段の文字までいっしょに読めてしまいます。

**② 道が必要以上に遠回りだった**

前は上限が無く「必要な長さに届いたら、4回に3回はゴールへ近づく」だけだった。
**帰り道のぶん**そのまま長くなり、必要な長さの2〜2.7倍になっていた。

- 上限を「必要な長さ＋2割」にした
- 上限の見かたを「いまの長さ」→「**いま まっすぐ帰ったら何マスになるか**」に直した
  （いまの長さで見ると、上限に着いてから帰り道ぶん そのまま超える。実測 上限75に対して85マス）
- 届いたあとにゴールへ向かう率を 0.75 → 0.9 に
- 道をのばして作り直すのは、**`place:`／`read:`（置き場所が足りない）で行きづまったときだけ**
  （STARTやGOALの置き場所が見つからない系ではのばしても効かず、1回が重くなるだけ。
   3段スタゴル2回で 19.9秒 → 6.8秒）

**実測（道の長さ・同じ乱数の種で8回ずつ）**

| 組み合わせ | 公開中 | 新 |
|---|---|---|
| 5段・26文字・20×20（まっすぐなら39マス） | 59〜77 | **53〜65** |
| 5段・42文字・20×20 | 73〜91 | **65〜83** |
| 2段・14文字・14×14（まっすぐなら27マス） | 37〜51 | **33〜51** |
| 1段・3文字・12×12（まっすぐなら23マス） | 23〜33 | **23〜31** |

盤のはしからはしまでの長さより短くはできないので、**文字が少ないときは迷路を小さくする**のが
いちばん効く（②の下に「この迷路には◯文字まで入ります」と出る）。

**③ ついでに見つけた本物のバグ：検算の範囲がひとつ足りなかった**

色のルールをもどしたら「4段スタゴル＋線けし」が 7/8・9.0秒 と重くなった。
行きづまりの内わけを見ると、半分が「1段めの読みがちがう（`read:0`）」。
1段めの道の上には よその文字が1つも無いのに、STEPが解いた道は記録より10〜40マス長かった。

原因：「STARTやGOALが変わる」段は、置き場所を増やすために道を遠回りにする。
そのとき**迷路ぜんたいを組み直す**（`rewireAsTree`）ので前の段の道まで変わる。
検算は入れてあったが、**確かめる範囲が `i` まで**だった。

`i + 1` に直しただけで：

- 4段スタゴル＋線けし **7/8・9.0秒 → 8/8・1.9秒**

### [2026-09-08] セッション195 — 迷路謎メーカー 答えの文字を固まらせない／「最短ルートが複数」をその場で直す

**指摘への対応（2点）**

| 指摘 | 対応 |
|---|---|
| 答え「わかる」の3文字が連続して置かれ、迷路を解かなくても答えが分かってしまう。できるだけ連続を避け、はじめ・なか・おわりに分けたい（はじめより、なか・おわりを多めに） | 置き場所の目あてを「空きマスの何番めか」から「**道すじのどのあたりか**」に変えた。道を3つに分けて重み **2:3:3** で配る（はじめを軽く）。あわせて**道すじのすきま**（`GAP`）を条件に加え、となり合うマスには置かない |

**① 答えの文字を固まらせない（`packages.js` の `placeOnFree` / `fillGaps`）**

3つ重なって「わかる」が3マス並んでいた。

1. **目あてが「空きマスの番号」だった** … 空きマスが少なくてかたまっていると、そのかたまりの
   中で均等にならべることになり、道の上ではとなり合う。→ `sectionAt()` / `wantCell()` で
   道すじの位置を目あてにした
2. **道すじの距離を見ていなかった** … 盤の距離 D≥2 だけでは、ぐねぐね曲がった道で
   となり合うマスが通ってしまう。→ `tryFit(D, GAP)` で道すじのすきまも見る（GAP≥2）
3. **間の1マスが空白だった** … GAP=2（間が1マス）を許すと「わ□か□る」で読めてしまう。
   → 文字と文字の**まん中のマスを `mustFill`** として、こさの設定に関係なく先に埋める

**ついでに直った：** 空きマスが少ないとき、目あて位置がちがう文字でも同じ空きマスに寄って
探索の目じるしがつぶれ、成り立たない並びばかり試していた。`wantIdx` を
`[i, free.length-(残り文字数)]` に収めた。行きづまりからのやり直しが増えるので
探索の上限も `4000` → `4000 + 空きマス×文字数×20`（上限40000）に。

**② 最短ルートを1本にする（`generate.makeShortestUnique`）**

STARTからの距離 `dS` とGOALからの距離 `dG` を1回ずつ測ると、
「どれかの最短ルートが通る辺」は `dS[a] + 1 + dG[b] === 最短の長さ` で見分けられる。
そのうち**残したい道の上にない辺だけ**をふさぐ。一方通行・ワープがあるときと、
残したい道がそもそも最短でないときは、理由を出して断る。
