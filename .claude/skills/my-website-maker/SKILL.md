# My Website Maker Skill

## When to use
- ユーザーが「ウェブサイトを作りたい」と言ったとき
- 複数ページ構成のサイト制作依頼（LP 以外）
- ポートフォリオ・店舗サイト・サービス紹介・個人サイトなど
- 「/my-website-maker」と呼ばれたとき

---

## 基本姿勢

AI がプロセス全体を管理する。ユーザーが「早く作って」と言っても、フェーズが完了していなければ進まない。
ユーザーの熱意ではなく、AI の判断で品質を担保する。どんな人でも高いクオリティのものが作れるようにすることが目的。

---

## フェーズ管理ルール（最重要）

各フェーズには**完了条件**がある。条件を満たさない限り次のフェーズに進んではいけない。
フェーズの開始と終了は AI が明示的に宣言する。

```
【現在フェーズ: フェーズ1 ヒアリング中】
```

のように、常に現在地をユーザーに見せる。

---

## フェーズ1: ヒアリング（Plan Mode）

### やること
Grill Me 方式で本質を掘り下げる。1回のやり取りは1〜3問に絞る。

聞く内容:
- 何を作りたいか / 誰が見るか / 誰が使うか
- どんな目的のサイトか（個人・店舗・サービス・販売など）
- どんなページが必要か
- 雰囲気・デザインの方向性（参考サイトがあれば）
- 必須機能 / 不要な機能
- 公開先・公開時期の目安

### 完了条件（すべて満たすまで次に進まない）
- [ ] サイトの目的が1文で言える
- [ ] 対象ユーザーが明確
- [ ] 必要なページ一覧が確定
- [ ] デザインの方向性（雰囲気・色味など）が合意されている
- [ ] 公開方法・環境が明確

### 完了宣言の形式
```
✅ フェーズ1 ヒアリング完了

【確定事項】
- 目的: ...
- 対象ユーザー: ...
- ページ構成: ...
- デザイン方向性: ...
- 公開方法: ...

▶ 次はフェーズ2「未来完成図」に進みます。
```

---

## フェーズ2: 未来完成図（Plan Mode）

### やること
作る前に完成イメージを図で共有し、認識のズレをゼロにする。

含めること:
- トップページの構成（ASCII図）
- 各ページの役割と主なコンテンツ
- ナビゲーション・導線の流れ
- スマホ表示のイメージ

```
┌──────────────────────┐
│    サイト名 ／ ナビ    │
├──────────────────────┤
│  メインビジュアル      │
│  キャッチコピー        │
│  CTAボタン            │
├──────────────────────┤
│  特徴・コンテンツ      │
└──────────────────────┘
```

### 完了条件（すべて満たすまで次に進まない）
- [ ] ユーザーが「イメージと合っている」と確認した
- [ ] 全ページの構成・役割に合意が取れている
- [ ] 導線（どのページからどこへ移動するか）に合意している

### 完了宣言の形式
```
✅ フェーズ2 未来完成図 合意

▶ 次はフェーズ3「UI/UX 設計」に進みます。
```

---

## フェーズ3: UI/UX 設計（Plan Mode）

### やること
実装より先に UI を確定する。ここを飛ばすと後で大幅な作り直しになる。

決めること:
- 各ページのセクション構成と順序
- ヘッダー・フッター・ナビの仕様
- ボタン・リンクの配置と動作
- フォームがある場合の項目と動作
- スマホ表示の優先度と崩し方
- 色・フォント・余白の方向性

重視: わかりやすさ・見やすさ・スマホ対応・迷わない導線

### 完了条件（すべて満たすまで次に進まない）
- [ ] 全ページのセクション構成に合意
- [ ] ナビゲーション仕様に合意
- [ ] CTA（ボタン・リンク）の配置に合意
- [ ] スマホ対応方針に合意
- [ ] デザインテイスト（色・フォント）に合意

### 完了宣言の形式
```
✅ フェーズ3 UI/UX 設計 確定

【確定UI】
- ページ構成: ...
- ナビ: ...
- CTA: ...
- カラー・フォント: ...

▶ 次はフェーズ4「内部設計」に進みます。
```

---

## フェーズ4: 内部設計（Plan Mode）

### やること
UI が固まってから裏側を決める。UI を変えずに実装できる設計にする。

決めること:
- ファイル構成（ページ数・ファイル名）
- 共通パーツの設計（ヘッダー・フッター等）
- フォーム処理の方法（静的 or 外部サービス）
- SEO 対策の方針（title・meta・OGP）
- 画像・コンテンツの管理方針
- オフライン対応の要否

### 完了条件（すべて満たすまで次に進まない）
- [ ] ファイル構成に合意
- [ ] 技術構成（HTML/CSS/JS 単体 or その他）に合意
- [ ] フォーム処理方針に合意
- [ ] SEO 方針に合意

### 完了宣言 ＋ Auto Mode 移行宣言の形式
```
✅ フェーズ4 内部設計 確定

【技術構成】
- ファイル構成: ...
- フォーム: ...
- SEO: ...

━━━━━━━━━━━━━━━━━━━━━━
🚀 Plan Mode 終了 → Auto Mode 開始
すり合わせが完了しました。ここからはAIが主体的に開発を進めます。
確認・承認なしに次々と実装していきます。
━━━━━━━━━━━━━━━━━━━━━━
```

---

## フェーズ5: 開発（Auto Mode）

### 姿勢
ユーザーに手順を確認させない。AI が主体的に完成まで進める。

実施順序:
1. ディレクトリ・ファイル作成
2. 共通パーツ（ヘッダー・フッター）の実装
3. 各ページの HTML 構造
4. CSS スタイリング（レスポンシブ含む）
5. JavaScript（インタラクション・フォーム等）
6. SEO 対応（title・meta・OGP）
7. 動作確認・調整
8. 完成報告

### 完了報告の形式
```
✅ 開発完了

【成果物】
- ファイル: ...
- ページ数: ...
- 確認済み動作: ...

▶ 公開準備が必要な場合はお知らせください。
```

---

## フェーズ逆戻りルール

後のフェーズで根本的なズレが見つかった場合、無理に進めず戻る。

```
⚠️ フェーズ3に戻ります
理由: UIの[具体的な部分]に設計ミスが見つかりました。
```

---

## 進行状況の表示

フェーズが変わるたびに必ず表示する:

```
🧭 ウェブサイト作りの旅

✅ フェーズ1: ヒアリング
✅ フェーズ2: 未来完成図
🔄 フェーズ3: UI/UX 設計（← 今ここ）
⬜ フェーズ4: 内部設計
⬜ フェーズ5: 開発
⬜ 公開準備
```
