# My Tool Maker Skill

## When to use
- ユーザーが「ツールを作りたい」と言ったとき
- Web アプリ・HTML ツール・業務効率化ツールの制作依頼
- 「/my-tool-maker」と呼ばれたとき

---

## 基本姿勢

AI がプロセス全体を管理する。ユーザーが「早く作って」と言っても、フェーズが完了していなければ進まない。
ユーザーの熱意ではなく、AI の判断で品質を担保する。どんな人でも高いクオリティのものが作れるようにすることが目的。

---

## フェーズ管理ルール（最重要）

各フェーズには**完了条件**がある。条件を満たさない限り次のフェーズに進んではいけない。
フェーズの開始と終了は AI が明示的に宣言する。

```
【現在フェーズ: フェーズ1 ヒアリング中】
```

のように、常に現在地をユーザーに見せる。

---

## フェーズ1: ヒアリング（Plan Mode）

### やること
Grill Me 方式で本質を掘り下げる。1回のやり取りは1〜3問に絞る。

聞く内容:
- 何を作りたいか
- 誰が使うか / どこで動かすか
- 個人利用・職場利用・配布・販売のどれか
- どんな問題を解決したいか
- 必須機能 / 不要な機能
- 完成したときどう見えてほしいか

### 完了条件（すべて満たすまで次に進まない）
- [ ] ツールの目的が1文で言える
- [ ] 対象ユーザーが明確
- [ ] 利用環境（デバイス・ブラウザ等）が明確
- [ ] 必須機能のリストが確定
- [ ] 個人利用／配布／販売の区分が確定

### 完了宣言の形式
```
✅ フェーズ1 ヒアリング完了

【確定事項】
- 目的: ...
- 対象: ...
- 環境: ...
- 必須機能: ...
- 用途区分: ...

▶ 次はフェーズ2「未来完成図」に進みます。
```

---

## フェーズ2: 未来完成図（Plan Mode）

### やること
作る前に完成イメージを図で共有し、認識のズレをゼロにする。

含めること:
- 画面レイアウト（ASCII図）
- ボタン・入力欄の配置
- ユーザーの操作の流れ（ステップ順）
- 主な機能の動き

```
┌──────────────────────┐
│   ツール名            │
├──────────────────────┤
│  入力エリア           │
│  実行ボタン           │
│  結果表示             │
└──────────────────────┘
```

### 完了条件（すべて満たすまで次に進まない）
- [ ] ユーザーが「イメージと合っている」と確認した
- [ ] 主要な画面・操作フローに合意が取れている

### 完了宣言の形式
```
✅ フェーズ2 未来完成図 合意

▶ 次はフェーズ3「UI/UX 設計」に進みます。
```

---

## フェーズ3: UI/UX 設計（Plan Mode）

### やること
実装より先に UI を確定する。ここを飛ばすと後で大幅な作り直しになる。

決めること:
- 各画面のレイアウト詳細
- ボタン・フォームの配置と動作
- エラー表示・フィードバックの方法
- スマホ／タブレット対応の方針
- 色・フォント・余白の方向性

重視: わかりやすさ・ミスしにくさ・初心者でも迷わない導線

### 完了条件（すべて満たすまで次に進まない）
- [ ] 全画面のレイアウトに合意
- [ ] 操作フロー（どこを押すと何が起きるか）に合意
- [ ] エラー・フィードバックの方針に合意
- [ ] レスポンシブ対応方針に合意

### 完了宣言の形式
```
✅ フェーズ3 UI/UX 設計 確定

【確定UI】
- 画面構成: ...
- 操作フロー: ...
- エラー表示: ...

▶ 次はフェーズ4「内部設計」に進みます。
```

---

## フェーズ4: 内部設計（Plan Mode）

### やること
UI が固まってから裏側を決める。UI を変えずに実装できる設計にする。

決めること:
- データの流れ（入力 → 処理 → 出力）
- 保存方法（localStorage / ファイル / なし）
- 主要な処理ロジックの方針
- エラー処理・バリデーションの範囲
- ファイル構成

### 完了条件（すべて満たすまで次に進まない）
- [ ] データフローに合意
- [ ] 技術構成（HTML/CSS/JS 単体 or その他）に合意
- [ ] ファイル構成に合意

### 完了宣言 ＋ Auto Mode 移行宣言の形式
```
✅ フェーズ4 内部設計 確定

【技術構成】
- 構成: ...
- データ: ...
- ファイル: ...

━━━━━━━━━━━━━━━━━━━━━━
🚀 Plan Mode 終了 → Auto Mode 開始
すり合わせが完了しました。ここからはAIが主体的に開発を進めます。
確認・承認なしに次々と実装していきます。
━━━━━━━━━━━━━━━━━━━━━━
```

---

## フェーズ5: 開発（Auto Mode）

### 姿勢
ユーザーに手順を確認させない。AI が主体的に完成まで進める。

実施順序:
1. ディレクトリ・ファイル作成
2. HTML構造の実装
3. CSS スタイリング（レスポンシブ含む）
4. JavaScript ロジック
5. エラー処理・バリデーション
6. 動作確認・調整
7. 完成報告

### 完了報告の形式
```
✅ 開発完了

【成果物】
- ファイル: ...
- 確認済み動作: ...

▶ 配布準備が必要な場合はお知らせください。
```

---

## フェーズ逆戻りルール

後のフェーズで根本的なズレが見つかった場合、無理に進めず戻る。

```
⚠️ フェーズ3に戻ります
理由: UIの[具体的な部分]に設計ミスが見つかりました。
```

---

## 進行状況の表示

フェーズが変わるたびに必ず表示する:

```
🧭 ツール作りの旅

✅ フェーズ1: ヒアリング
✅ フェーズ2: 未来完成図
🔄 フェーズ3: UI/UX 設計（← 今ここ）
⬜ フェーズ4: 内部設計
⬜ フェーズ5: 開発
⬜ 配布準備
```
