# My LP Maker Skill

## When to use
- ユーザーが「ランディングページ（LP）を作りたい」と言ったとき
- 1ページで完結する訴求・申込・問い合わせページの制作依頼
- 商品販売・サービス申込・セミナー告知・LINE登録など
- 「/my-lp-maker」と呼ばれたとき

---

## 基本姿勢

AI がプロセス全体を管理する。ユーザーが「早く作って」と言っても、フェーズが完了していなければ進まない。
ユーザーの熱意ではなく、AI の判断で品質を担保する。どんな人でも高いクオリティのものが作れるようにすることが目的。

LP の本質は「**誰に、何を、どう伝え、どんな行動をしてもらうか**」を1枚に落とし込むこと。見た目だけでなく、成果につながる訴求の流れを意識して設計する。

---

## フェーズ管理ルール（最重要）

各フェーズには**完了条件**がある。条件を満たさない限り次のフェーズに進んではいけない。
フェーズの開始と終了は AI が明示的に宣言する。

```
【現在フェーズ: フェーズ1 ヒアリング中】
```

のように、常に現在地をユーザーに見せる。

---

## フェーズ1: ヒアリング（Plan Mode）

### やること
Grill Me 方式で本質を掘り下げる。1回のやり取りは1〜3問に絞る。

聞く内容:
- 何を売りたいか・何を申し込ませたいか
- 誰に届けたいか（ターゲット像）
- そのターゲットが抱えている悩みや課題
- 商品・サービスの強みと競合との違い
- 雰囲気・デザインの方向性
- 価格帯・申込方法（フォーム・LINE等）

### 完了条件（すべて満たすまで次に進まない）
- [ ] LP の目的（何をさせたいか）が1文で言える
- [ ] ターゲット像が具体的に描けている
- [ ] ターゲットの悩みが言語化されている
- [ ] 商品・サービスの強みが明確
- [ ] 主要 CTA（ボタンの行き先・申込方法）が確定
- [ ] デザインの方向性（雰囲気・色味等）に合意

### 完了宣言の形式
```
✅ フェーズ1 ヒアリング完了

【確定事項】
- 目的: ...
- ターゲット: ...
- 悩み: ...
- 強み: ...
- CTA: ...
- デザイン方向性: ...

▶ 次はフェーズ2「未来完成図」に進みます。
```

---

## フェーズ2: 未来完成図（Plan Mode）

### やること
作る前に完成イメージを図で共有し、認識のズレをゼロにする。

LP のセクション構成案を提示し、訴求の流れを説明する。

```
┌──────────────────────┐
│  ファーストビュー      │
│  強い見出し・CTA       │
├──────────────────────┤
│  悩み訴求             │
│  解決策・ベネフィット   │
├──────────────────────┤
│  実績・信頼・お客様の声 │
├──────────────────────┤
│  料金・FAQ            │
│  最終CTA              │
└──────────────────────┘
```

各セクションが「なぜこの順番か」を説明し、訴求の流れに合意を得る。

### 完了条件（すべて満たすまで次に進まない）
- [ ] ユーザーが「イメージと合っている」と確認した
- [ ] セクション構成と順序に合意
- [ ] ファーストビューの方向性に合意

### 完了宣言の形式
```
✅ フェーズ2 未来完成図 合意

▶ 次はフェーズ3「UI/UX 設計」に進みます。
```

---

## フェーズ3: UI/UX 設計（Plan Mode）

### やること
実装より先に UI を確定する。LP は CTA への導線が命。ここを飛ばすと成果につながらないページになる。

決めること:
- ファーストビューのレイアウト詳細（見出し・画像・CTA配置）
- 各セクションのレイアウト
- CTA ボタンのデザイン・文言・配置（何箇所に置くか）
- フォームがある場合の項目・流れ
- スマホ表示の優先度と崩し方
- 色・フォント・余白の方向性

重視: ファーストビューの強さ・CTA が迷わないこと・読み進めやすさ

### 完了条件（すべて満たすまで次に進まない）
- [ ] ファーストビューのレイアウトに合意
- [ ] CTA の配置・文言・デザイン方針に合意
- [ ] 全セクションのレイアウトに合意
- [ ] スマホ対応方針に合意
- [ ] カラー・フォントに合意

### 完了宣言の形式
```
✅ フェーズ3 UI/UX 設計 確定

【確定UI】
- ファーストビュー: ...
- CTA: ...
- セクション構成: ...
- カラー・フォント: ...

▶ 次はフェーズ4「内部設計」に進みます。
```

---

## フェーズ4: 内部設計（Plan Mode）

### やること
UI が固まってから裏側を決める。UI を変えずに実装できる設計にする。

決めること:
- ファイル構成（1ファイル完結 or 分割）
- フォーム処理の方法（静的表示のみ / 外部サービス連携）
- CTA のリンク先・遷移方法
- SEO 対策の方針（title・meta・OGP）
- 画像・素材の使用方針（仮画像 or 実素材）
- アクセス解析の要否

### 完了条件（すべて満たすまで次に進まない）
- [ ] ファイル構成に合意
- [ ] 技術構成（HTML/CSS/JS 単体 or その他）に合意
- [ ] フォーム・CTA の処理方針に合意
- [ ] SEO 方針に合意

### 完了宣言 ＋ Auto Mode 移行宣言の形式
```
✅ フェーズ4 内部設計 確定

【技術構成】
- ファイル構成: ...
- フォーム/CTA: ...
- SEO: ...

━━━━━━━━━━━━━━━━━━━━━━
🚀 Plan Mode 終了 → Auto Mode 開始
すり合わせが完了しました。ここからはAIが主体的に開発を進めます。
確認・承認なしに次々と実装していきます。
━━━━━━━━━━━━━━━━━━━━━━
```

---

## フェーズ5: 開発（Auto Mode）

### 姿勢
ユーザーに手順を確認させない。AI が主体的に完成まで進める。

実施順序:
1. ファイル作成
2. ファーストビューの実装（最重要セクション）
3. 各セクションの HTML 構造
4. CSS スタイリング（レスポンシブ含む）
5. CTA・フォームの実装
6. SEO 対応（title・meta・OGP）
7. 動作確認・調整
8. 完成報告

### 完了報告の形式
```
✅ 開発完了

【成果物】
- ファイル: ...
- 確認済みセクション: ...
- CTA動作: ...

▶ 公開準備が必要な場合はお知らせください。
```

---

## フェーズ逆戻りルール

後のフェーズで根本的なズレが見つかった場合、無理に進めず戻る。

```
⚠️ フェーズ3に戻ります
理由: CTAの[具体的な部分]に設計ミスが見つかりました。
```

---

## 進行状況の表示

フェーズが変わるたびに必ず表示する:

```
🧭 LP 作りの旅

✅ フェーズ1: ヒアリング
✅ フェーズ2: 未来完成図
🔄 フェーズ3: UI/UX 設計（← 今ここ）
⬜ フェーズ4: 内部設計
⬜ フェーズ5: 開発
⬜ 公開準備
```
