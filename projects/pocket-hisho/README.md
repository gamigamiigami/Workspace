# ポケット秘書

全国をまわる**セミナー講師**のための、オンライン秘書アプリ。
伊神さんが作って、知り合いの講師の方に渡すツール（伊神さん自身は使わない）。

**👉 動かす手順は [SETUP.md](./SETUP.md) を見てください。**

---

## これは何か

> 日程はカレンダー、会場の住所はメール、新幹線の予約はアプリ、ホテルは別のメール、
> 主催者の電話番号はLINE、運賃やホテル代のレシートは財布の中……
> → **当日、駅で「何時入りだっけ？担当者の番号どこ？」になる。**

これを1か所にまとめて、**時刻が来たらスマホに知らせる**ための道具です。

背骨は2つだけ。

1. **1つのセミナー＝1枚のカード。当日は開くだけで全部わかる。**
2. **覚えておくのはアプリの仕事。人は思い出さなくていい。**

## できること

| | 中身 |
|---|---|
| 📅 **予定** | 日・週・月・年の4段ビュー。**見る範囲が広いほど情報を減らす**。どこをタップしても「日」に着地 |
| 📋 **1件の中身** | 会場（地図・住所コピー）／連絡先（タップで電話・メール）／当日のながれ／移動と運賃／宿泊とホテル代／内容／持ち物チェック／メモ。**入力画面は「きほん」「ばしょ」だけ開いていて、ほかはたたんである**（分かったときに開いて入れる） |
| ☑️ **やること** | 期限つきのタスク。予定にひもづけられる。期限切れ・きょう・3日以内で自動的にまとまる |
| 🔔 **通知** | 前日／2時間前／30分前／やることの期限／毎朝のまとめ。**アプリを閉じていても届く** |
| 📆 **カレンダー連携** | アプリ→カレンダー（購読用URL）と、カレンダー→アプリ（読み取り）の**両方向**。ログイン不要 |
| 💻 **同期** | スマホとパソコンで同じものが見える |
| 📴 **オフライン** | 電波が無くても開ける。入力もでき、つながったときにまとめて送る |
| 💰 **かかったお金** | **運賃・ホテル代・その他**を記録するだけ。「2万8400」「28,400円」のような書き方もそのまま読める。年ごとにエクセル用の表（CSV）に書き出せる |
| 🚀 **はじめの準備** | 最初に開いたとき自動で出る案内。**その端末に合わせて**（iPhone／Android／LINEの中／パソコン）次にやることを1つずつ出す。できたものは自動で「済み」になる |
| 🔗 **招待リンク** | 伊神さんが作ってLINEで送るだけ。講師の方は**合言葉なし**で入れる（14日間有効） |

**費用は0円**（Cloudflare の無料枠のみ）。外部の有料サービスは使っていません。

## 作り

```text
  📱 スマホ（ホーム画面のアイコン）        💻 パソコン（ブラウザ）
        └─────────── 同じURL・同じデータ ──────────┘
                          │
              ┌───────────▼──────────────┐
              │  Cloudflare Workers（無料）│
              │   ├ アプリ画面を配る        │
              │   ├ 予定・やることを保管(D1)│
              │   ├ 1分ごとの見回り ────────┼──▶ 📲 Webプッシュ通知
              │   ├ 購読用URL(.ics)を配る ──┼──▶ 📅 Google / iPhone純正
              │   └ 外部カレンダーを取り込む ◀┼─── 📅 シークレットアドレス(iCal)
              └──────────────────────────┘
```

### なぜ「ふつうのアプリ」ではなく PWA なのか

App Store に出すには **Mac（Xcode）と Apple Developer Program（年間約1.5万円）** が要ります。
どちらも無いという条件だったので、**PWA**（ブラウザで開くが、ホーム画面に追加するとアプリとして
振る舞う仕組み）を選びました。App Store不要・Mac不要・無料で、iPhone / Android / パソコンが
**1つのコードで動きます**。

### なぜ Google Calendar API（OAuth）を使わないのか

正攻法の OAuth 連携は、Googleの審査を通していないアプリだと
**7日ごとにログインし直しが必要**になります。人に渡す道具としては確実に壊れます。
代わりに、**認証の要らないICSのやりとり**で実質双方向を実現しています。

## 直すときに壊さないための決まりごと

- **日付は必ず `shared-date.js` を通す。** サーバーは世界標準時で動くので、
  日本時間で数えないと日付が1日ずれる。
- **データの形をそろえるのは `normalize*()` だけ。** 入口が3つ（画面／バックアップ／古い保存ぶん）
  あるので、そろえる処理を分散させない。
- **色はすべてCSS変数。** 暗い画面では変数の中身だけ差しかえる。
  濃い色の上に置く文字は `--on-navy`（白で直書きすると暗い画面で読めなくなる）。
- **入力中は画面を描きなおさない。** 日本語入力の変換がとぎれるため。読み取りは保存時にまとめて。
- **画面に出す文字は必ず `esc()` を通す。**
- **`<fieldset>` には `min-inline-size: 0` が要る。** 既定では中身より狭くならず、スマホで横にはみ出す。
- **Service Worker で「転送された応答」を画面に返さない。** `/index.html` はサーバーが `/` へ
  転送するため、取っておいた応答に転送の印が付き、**そのまま返すとオフラインで真っ白になる**。
  `shellResponse()` で作り直している。
- **通知の「送ったか」は `sent` テーブルの key で判定する。** 予約テーブルを別に持つと
  予定を編集したときにズレる。key は予定ID＋種類＋時刻から毎回計算する。
- **お金は `cost: { fare, hotel, other, otherNote }` だけ。** 金額の読み取りは `toYen()`、
  合計は `costOf()`、表は `buildCostCsv()`（すべて `shared-model.js`）。
  前の版の `money` 配列（講演料・経費）は `normalizeCost()` が運賃・ホテル代・その他に読みかえる
  （講演料＝入ってくるお金は記録しなくなったので捨てる）。
- **表（テーブル）を足すときは `src/schema.js` の `SCHEMA` に `CREATE TABLE IF NOT EXISTS` で書く。**
  すでに動いている保管庫へ列を足すときは `UPGRADES` に書く。どちらも次に動いたとき自動で実行される。
- **ログインの入口は3つ（合言葉・招待リンク・6けたの番号）。** まちがえたときの鍵
  （8回で15分止める）は `checkLock / recordFail` を3つとも通す。入口を足すときも同じにする。
- **iPhoneは Safari と「ホーム画面のアイコン」で保存場所が別。** ログインを渡すため、
  Safari で開いている間に6けたの番号を作り、①アドレス欄（`?h=番号`）と
  ②説明書（`/app.webmanifest?h=番号` の `start_url`）の両方に入れている。
  どちらかが渡ればアイコン側で自動的にログインする。
- **Service Worker はネット優先（2.5秒で見切って手元の取り置き）。** 「手元優先」にすると
  新しい画面と古いプログラムが混ざって動く瞬間ができ、画面が壊れる。

### 動作確認用の窓口（ブラウザのコンソールから）

## テスト

```bash
cd projects/pocket-hisho
npm install                       # wrangler（初回のみ）
npm install --no-save playwright  # 画面のテストをするときだけ（公開には使わない）

# ① 通信のいらない部分（日付・お金の読み取り・カレンダー形式・暗号化・通知の判定）
node tests/test-core.mjs          # 100項目
node tests/test-remind.mjs        #  61項目

# ② サーバー全体（手元でサーバーを起動した状態で）
#    database_id は空のままでよい。表は自動で作られ、合言葉はテストが自分で決める（test-pass-1234）
npx wrangler dev --local --port 8788 &

node tests/test-api.mjs           # 151項目（まっさらな状態）／148項目（2回目以降）
node tests/test-ui.mjs            # 131項目（ブラウザを動かす）
```

**まっさらな状態で合計 443項目**。どの順番で流しても同じ結果になるようにしてあります
（それぞれのテストが、はじめに中身を空にし、終わりに自分の登録を片づける）。
とくに次を実際に動かして確かめています。

- **作った人（パソコン）と講師の方（iPhone）の両方の流れ**：はじめての合言葉 → はじめの準備 →
  招待リンクをLINEで送る → iPhoneのSafariで開く → ホーム画面のアイコンから開く（番号で自動ログイン）→
  通知をオン → 自動のテスト通知が届いて、その端末の鍵で読める
- 番号が渡らなかったとき（手で入れる）・LINEの中で開いたとき・Androidのとき
- 運賃「2万8400」→ 28,400円、古い `money` データの読みかえ、年ごとの表（CSV）の中身
- **通知を暗号化して偽の通知サーバーへ送り、端末の鍵で復号して中身を確認**（他人の鍵では読めないことも）
- **本番と同じ経路（1分ごとの見回り → 通知）**で通知が届くこと、二度目は送られないこと
- 外部カレンダーの取り込み（繰り返し予定の展開・消えた予定の削除・つながらないURL）
- 電波を切った状態でのアプリ起動・運賃の入力・つながったときの送信
- タップ領域44px以上・横スクロールなし、明暗どちらの画面でもコントラスト比4.5以上
