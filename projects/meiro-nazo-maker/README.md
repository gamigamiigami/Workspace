# 迷路謎メーカー

謎解き制作者むけの **連鎖型「迷路謎」制作ツール**。
ふつうの迷路メーカーではなく、**解き方を先に設計すると、その解き方が成立する迷路が自動でできる**道具。

公開URL：https://gamigamiigami.github.io/Workspace/projects/meiro-nazo-maker/

---

## ふつうの迷路メーカーとの違い

```
【ふつう】 迷路をランダムに作る → 人が解く

【これ】   解き方を設計する
           → 正解ルートを描く
           → そのルートが「たった1本の最短ルート」になる迷路を自動生成
           → ルートの上に文章を自動配置＋ダミーをまく
           → ルートから情報を抽出（赤い文字だけ読む など）
           → 出た指示を実行（赤い線を消す など）
           → 盤面が変化する
           → もう一度解く → さらに情報 → 最終こたえ
```

## 作れる謎の例（同こんの見本）

```
STEP1  最短ルートを通る
STEP2  ルートの文字を読む
STEP3  赤だけ読む         → 「あかいせんをけせ」
STEP4  赤の線を消す        → 盤面が変わる（近道ができる）
STEP5  変わった迷路の最短ルートを通る
STEP6  ルートの文字を読む
STEP7  黄だけ読む         → 「よくできました」
STEP8  最終こたえ
```

はじめて開くとこの見本が入っている。左のSTEPを押すと、その時点の盤面を見られる。

## しくみ（なぜ正解が1本に決まるのか）

1. いったん全部のマスのあいだに壁を立てる
2. 描いてもらった正解ルートの上だけ壁をこわして道にする
3. 残りを「すでに道になっているところから枝分かれさせる」形で掘る（ランダムPrim法）

輪っか（ぐるっと回れる道）が一度もできないので、できあがりは**閉路のない迷路**になる。
閉路が無い迷路では**どの2点をとっても道は必ず1本だけ**なので、描いたルートが自動的に
「たった1本の最短ルート」になる。

「わき道の多さ」を上げると輪っかを足すが、1本足すたびに検算して
**正解ルートが1本のままのときだけ採用**するので、この保証は崩れない。

## 使い方（3分でできる最短の流れ）

1. ツールバーの **ルート** で、通してほしい道を指でなぞる
2. 右パネル **② 正解ルート → 「このルートを正解にする」**
3. 右パネル **③ 文字を置く** に文章を入れて「ルートの上に置く」
4. 「ダミーをまく」でまわりにまぎらわしい文字をちらす
5. 左パネルで **STEP** を足して、「赤だけ読む」「赤の線を消す」…とつなげる
6. 右パネル **⑦ チェック** が ✓ ばかりになれば、謎として成立している
7. **🖨 印刷** か **🖼 画像で保存**

### キーボード

| 操作 | キー |
|---|---|
| もどす / すすむ | Ctrl+Z / Ctrl+Y |
| 消す | Delete |
| 複製 | Ctrl+D |
| ぜんぶ選ぶ | Ctrl+A |
| 文字入力中に右のマスへ | Enter または Tab |

指2本で拡大・移動できる。

## 入っている機能

| 分類 | 内容 |
|---|---|
| 迷路編集 | 大きさ変更・壁の追加/削除・START/GOAL（複数可）・Undo/Redo・ズーム/パン・グリッド |
| 正解ルート | ペンで描く／途中から描き直す／消しゴム／長さ表示／**ルートから迷路生成**／最短判定・複数警告 |
| 情報配置 | ひらがな・カタカナ・漢字・英字・数字・記号／色6色／大きさ／ドラッグ移動・複製・範囲選択・削除 |
| 自動配置 | ルート上に文章を自動配置（順・逆順・等間隔・指定マス）／ダミー文字の自動散布 |
| 抽出 | 通過文字・色フィルター（この色だけ／この色いがい）・読み順6種・奇数/偶数番目・種類しぼり |
| ギミック | ○を通る／×を避ける／順番指定／一方通行／START変更／GOAL変更（記号でも指定可）／壁を消す／文字を消す／左右反転・上下反転・180度回転／ワープ |
| 連鎖 | STEPエディタ・状態変化・再探索・ルート形状取得・別盤面への転写・囲まれた領域 |
| 検証 | 到達可能／最短一致／最短が複数／○全通過／×回避／一方通行の詰み／ワープの近道／STEP間の状態変化／想定こたえとの一致 |
| 出力 | 制作者モード／プレイヤーモード／印刷（白黒対応・凡例つき）／PNG保存／作品の保存・書き出し |

「消す」は **見た目だけ消す / 無効にする（通れる・読めなくなる） / 完全に消す** の3種類を使い分けられる。

## ファイル構成

```
meiro-nazo-maker/
├── index.html   画面とスタイル
└── js/
    ├── model.js     データ構造（Maze / Wall / Element / Route / Start / Goal）
    ├── engine.js    最短経路・経路の本数・一方通行・○必須・×回避・ワープ
    ├── generate.js  正解ルート → 迷路の自動生成
    ├── render.js    描画（画面・印刷・PNG・プレイヤー画面で共通の1関数）
    ├── ops.js       ギミック部品のレジストリ（入力→処理→出力）＋抽出
    ├── steps.js     STEPの連鎖・State計算・自動検証
    ├── editor.js    キャンバス操作・Undo/Redo・ズーム/パン・その場文字入力
    └── app.js       画面の配線
```

### 設計上の約束（次に触るときのために）

- **設計図（Maze）と、STEPを通したあとの盤面（State）を分ける。**
  STEPを走らせるときは毎回 Maze を複製してから変換をかけるので、
  STEPをいじっても設計図は壊れない。STEPの結果の盤面は**見るだけ**（編集不可）。
- **描画関数は `MZ.render.drawBoard` の1本だけ。**
  画面・印刷・PNG・プレイヤー画面は全部これを呼び、違いは引数だけ。
  （画面用と印刷用を分けて書くと「印刷にだけ何かが無い」が必ず起きる）
- **ギミックは `MZ.ops.register()` に1つ足すだけで増える。** if文の場合分けは作らない。
- 読み順・絞り込みは `MZ.ops.orders` / `MZ.ops.filters` に名前で登録してあるので、あとから種類を足せる。
- 外部ライブラリ・CDNなし。`file://` で直接開いても動く（ES Modulesを使っていないため）。

## 完了基準

- [x] 正解ルートから迷路を生成し、「たった1本の最短ルート」になることを100回試して確認
- [x] 一方通行・○必須・×回避・ワープ・壁の無効化の探索を検証
- [x] 反転・回転が「2回で元に戻る」ことと、一方通行の向きも一緒に直ることを確認
- [x] STEP連鎖の通し確認（最短→赤だけ読む→赤線を消す→再探索→黄だけ読む→こたえ）
- [x] 画面・印刷・PNGが同じ描画関数を通ることを確認
- [x] iPad縦持ち（768px）で、指でルートが描けること・ピンチ拡大・横スクロールなしを確認
- [x] 日本語入力（変換中の文字が勝手に確定されない）を確認
- [ ] **iPad実機テスト待ち**（指の描き心地・パネル切りかえ・文字の直しやすさ・印刷の見え方）

## 動かない・困ったとき

- **保存できない**：プライベートモードでは保存できないことがある。「ファイルに書き出す」を使う
- **最短ルートが複数と言われる**：「このルートを正解にする」を押し直すと1本に作り直せる
- **文字が読めない**：白黒印刷なら「白黒で印刷する」にチェック（色を線のもようと文字の飾りで見分ける）
