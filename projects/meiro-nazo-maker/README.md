# 迷路謎メーカー

謎解き制作者むけの **迷路謎じどう作成ツール**。
**「どんな謎にするか」を決めると、その条件を全部みたす迷路のほうを自動で作ります。**

公開URL：https://gamigamiigami.github.io/Workspace/projects/meiro-nazo-maker/

---

## ぜんぶ1ページ（画面の切りかえはありません）

上から下へ、1 → 5 の順に進みます。**作るところと直すところが同じページ**にあるので、
「今どっちの画面にいるのか」を気にしなくてよくなりました。

```
1 どんなしかけを入れるか えらぶ（いくつでも組み合わせられます）
2 段ごとの文章を入れる（段ごとに色・読む順も変えられます）
3 「✨ 自動で作る」を押す
4 できたものを見る・直す ── 問題文／段の切りかえタブ／迷路／道具 が1画面に並びます
5 もっと細かく直す（使いたいときだけ）── STEPの並べかえ・チェック・印刷設定 など
```

### 4 に出る迷路は「絵」ではなく本物の盤面です

ここがいちばん大事なところです。
**4 に映っている迷路そのものが編集対象**なので、見ているものをその場で直せます。

- ツールバーで **もじ・きごう・かべ・ルート** を置く／**けす** で消す
- **えらぶ** でドラッグして動かす、範囲ドラッグでまとめて選ぶ
- 選んだものの **色・大きさ・複製・削除** は、迷路のすぐ下の帯にあります
- 上のタブで **問題 ↔ n段めの答え** を切りかえる（迷路は同じまま、通り道だけ変わります）
- **↶ ↷** で迷路の変更をもどす・すすむ（ツールバーの右がわ）

> 前の版は「かんたん作成の下に、これまでの編集画面をそのままぶら下げる」形でした。
> 結果の絵と編集用の盤面が別々にあり、直すには下の別の盤面まで行く必要がありました
> （伊神さんの指摘：「ページの統合とはそういうことではない」）。
> **絵をやめて盤面を1つにした**のが今の形です。

### 迷路の全体・問題文・切りかえボタンが同時に見えます

盤面の高さは `.canvas-wrap` の `height: clamp(240px, calc(100vh - 620px), 430px)` で決めています。
「箱ぜんたい」ではなく「迷路が映る部分」の高さを直接おさえているのは、
ツールバーの行数が画面の幅で変わるからです（せまい画面でツールバーが3行になると、
箱の高さを決める方式では迷路だけがつぶれて豆つぶになっていました）。
横幅が 1000px 以上あるときは、こたえとボタンを迷路の右に置いて、そのぶん迷路を大きくします。

最初から自分で道を描きたいときは、1 の下の「✏️ 最初から自分で作る」を押すと、
4 の盤面で「ルート」ツールを持った状態から始められます。

上のバーの「✏️ 迷路を直す」で 4 まで飛べます。
5 の中の「⬆ 上（作るところ）へ」で、いつでも 1 に戻れます。

同じ設定（大きさ・文字の量・わき道・START/GOAL）は**上と下の両方に出ますが、中身は1つ**です。
どちらで変えても、もう片方にもそのまま反映されます。

**「STARTからGOALまで、いちばん短い道を通る」はどの謎にも必ず入る土台**なので、選択肢には出しません。
そのうえに「しかけ」を重ねていきます。

できあがった迷路は、かならず次の条件を満たしています（満たさないものは捨てて作り直します）。

- STARTからGOALへの道が **1本だけ**、または **次に短い道と4マス以上ちがう**
- **同じ通路を2回通らずに解ける**（交差はOK、行って戻るのはNG）
- 入れた文章が、そのとおりに読める
- 段が変わると本当に道が変わり、次の段も1本だけの道になる

## 組み合わせられる しかけ（9つ・同じものを何回でも重ねられます）

| | しかけ | 何が起きるか |
|---|---|---|
| 🔴 | 色でしぼって読む | 通った道の「赤い文字**だけ**」を読みます。**2回えらぶと 赤→青 と同じ道を読み直す段**が増えます |
| 🚫 | 色いがいを読む | 「赤い文字**いがい**を読め」の言い方にします。こたえは黒、まぎれ文字が赤になります |
| ⭕ | ○を全部通る | ○のマスを全部通ってからGOALへ |
| ❌ | ×を通らない | ×のマスを避けて進みます |
| ✂️ | 線を消して次の段へ | 読んだ指示どおりに色つきの線を消すと道が変わり、もう一度解く |
| ⭐ | STARTが変わって次の段へ | 読んだ指示どおりに★から出発しなおす |
| 🎯 | GOALが変わって次の段へ | 読んだ指示どおりに☆を新しいGOALにする |
| 🌟 | STARTもGOALも変わって次の段へ | 読んだ指示どおりに★から☆へ、出発点も終点も変えなおす |
| 🔃 | 読む順番を変える | 通った順ではなく **うしろから／左→右／右→左／上→下／下→上** の順に読ませます |

**🔴 と 🚫 は正反対の言い方なので、いっしょには選べません**（選ぼうとすると理由が出ます）。
**🔃 読む順番** はカードを選ぶと下に「読む順」のえらぶ欄が出ます。

**カードは何回でも押せます。**押した回数だけ段が増え、**最大7段**まで組めます。
（例：`色でしぼって読む ×3` ＝ 同じ迷路を 赤 → 青 → 黄 と読み直す3段の謎）

段が増えるごとに、その段の文字の色が **赤 → 青 → 黄 → 緑 → 紫** と変わります（紫のあとは
紫のまま。同じ色は2段までしか使えないので、色でしぼる段は実質6段までです。
色が同じでも、あとで説明する「重ならない道」の仕組みで区別しています）。
「線を消す」は線の色を段ごとに必ず変えるので **5回まで**（6回めは選べません）。

**STARTやGOALが変わる段を2回め以降くり返すと、目印の記号を変えます。**
1回め ★☆ → 2回め ■□ → 3回め ▲△ → 4回め以降 ◆◇／●♪／↑→ と、
くり返すたびに違う記号にするので、同じ★☆が2つあって迷う、ということが起きません。

### 段をつなぐ指示文は、しかけに合わせて自動で入ります

| しかけ | 前の段のこたえ（初期値） |
|---|---|
| 線を消して次の段へ | あかいせんをけせ |
| STARTが変わる | ほしからやりなおし |
| GOALが変わる | ほしまでいけ |
| STARTもGOALも変わる（カード1枚で選ぶ／「STARTが変わる」と「GOALが変わる」を続けて選んでも同じ1段にまとまります） | ほしからほしへ |
| 読み方を変えて読み直す | あおいもじだけよめ／あかいもじいがいをよめ |

### 段の色の既定ルール

伊神さんが決めたルールです。

| しかけ | 次の段の色 |
|---|---|
| 色でしぼって読み直す | **次の色へ進む**（赤→青→黄→緑→紫） |
| 線を消す／STARTが変わる／GOALが変わる／STARTもGOALも変わる | **赤にもどす** |

赤にもどすのは「ここで場面が切りかわった」を色でも表すためです。

```
色でしぼって読む → 色でしぼって読む → STARTもGOALも変わる
　　　あか　　　→　　　あお　　　→　　　あか（ここでもどる）
```

### 線を消す段でも、2回はさめば赤にもどります

伊神さんの見立て：
> せんをけすも、もともとのルートと全然違うルートを通ることができれば同じ色の文字でもいいはず。
> そのための遠回りさせる設定です？

**そのとおりです。** 段の色は「文字が何色で書かれるか」だけでなく、
**「その段の文字を置けない場所」**も決めています。
同じ色の段が2つあると、片方を読むときにもう片方の文字までいっしょに読めてしまうので、
その2段は**おたがいに「自分だけが通るマス」**を持っていなければなりません。
遠回りを作るしかけは、まさにそのために道を分けています。

問題は「どれだけ分けられるか」です。実測しました。

| 分ける大きさ（前後それぞれ） | 作れる率 | 時間 |
|---|---|---|
| 3マス（線を消す1回ぶん） | 8/8 | 0.2〜0.6秒 |
| 7〜8マス | 8/8 | 2.1〜3.2秒 |
| 11〜12マス | 5/8 | 5〜10秒 |
| 14マス | 1〜5/8 | 9〜12.5秒 |

つまり **線を消す1回ぶんの分け方では足りず、2回ぶん分ければ足ります**。
実測でも、赤→赤（線けし1回）は **2/8** しか作れませんが、
赤→青→赤（線けし2回）は **7〜8/8** 作れます。

そこで、**同じ色にもどせるのは「線を消す」を2回はさんだあと**にしました。

```
色でしぼる → 線を消す → 線を消す
　　あか　→　あお　→　あか（2回はさんだので、もどせる）

色でしぼる → 線を消す
　　あか　→　あお（1回では道がにすぎるので、もどせない）
```

STARTやGOALが変わる段は道がまるごと別物になるので、**1回で赤にもどせます**。

**同じ色を使えるのは2段まで**です。3段が同じ色になると急に作れなくなります
（実測：5段スタゴル2回＋線けしで、3段が赤だと 3/12・42秒。2段までなら 12/12・4秒）。

**もうひとつ、「線を消す」段どうしは線の色をぜったいに使い回しません**
（消す線の色はその段の色になるので、同じ色が2回出ると
問題用紙の「あかいせんをけせ」でほかの段の線まで消えてしまいます）。

**作れなかったときは、どの段を何色にすればよいかまで出します。**

> 4段めは 1段め と同じ**赤**なので、その2つの段が**おたがいに自分だけ通る道**を
> 持てるところまで道を分ける必要があり、そのぶん作りにくくなっています。
> 直し方 1. ②の「色：」欄で **4段めを別の色**にする（いちばん効きます）…

赤にもどす形は、色を散らす形より**作りにくく・遅い**です（実測 8/8・0.3〜0.8秒 →
4〜8/8・1〜3.5秒）。それでも「赤＝場面が切りかわった」が伝わるほうを既定にしています。

### 道は「必要なぶんだけ」長くします

文字を離して置ける余地は、**盤の広さではなく道の長さ**で決まります。
そこで道の長さは、必要なマス数から決めています。

| きまり | 中身 |
|---|---|
| 下限 | 段ごとに要るマス数を うしろの段から逆算した `req[0]` |
| **上限** | その **＋2割**（すくなくとも6マス） |
| 足りないとき | 同じ大きさのまま、必要な長さの**1割ずつ**のばして作り直す（6割まで） |

**上限が要る理由：** 前は上限が無く、「必要な長さに届いたら、4回に3回はゴールへ近づく」
だけだったので、遠くまで行ってから帰ってくるぶん、**必要な長さの2〜2.7倍**になっていました
（伊神さんの指摘：「かなり遠回りになってる」）。

上限の見かたにもコツがあります。「いまの長さ」で見ると、上限に着いてからゴールまでの
帰り道ぶん（10マスなど）をそのまま超えてしまうので、
**「いま まっすぐ帰ったら何マスになるか」**で見ます。

**のばすのは「置き場所が足りない」で行きづまったときだけ。**
STARTやGOALの置き場所が見つからない系では、のばしても効かないのに1回が重くなります
（3段スタゴル2回で 8.0秒 → 19.9秒 になっていました）。

**実測（同じ乱数の種で8回ずつ・前 → 後）**

| 組み合わせ | 前の道の長さ | 後の道の長さ |
|---|---|---|
| 5段・26文字・20×20（まっすぐなら39マス） | 59〜77 | **53〜65** |
| 5段・42文字・20×20 | 73〜91 | **65〜83** |
| 2段・14文字・14×14（まっすぐなら27マス） | 37〜51 | **33〜51** |
| 1段・3文字・12×12（まっすぐなら23マス） | 23〜33 | **23〜31** |

盤のはしからはしまでの長さより短くはできないので、**文字が少ないときは
迷路を小さくする**のがいちばん効きます（②の下に「この迷路には◯文字まで入ります」と出ます）。

### 段ごとに色・読む順を個別に変えられます

②の欄には、段ごとに小さな「色：」のえらぶ欄が出ます。上の既定ルールで決まった色を、
その段だけ好きな色に変えられます（例：赤→青→STARTが変わる、で既定は赤にもどりますが、
場面に合わせて青のままにしたい、などの個別指定ができます）。

「🔃 読む順番を変える」カードを選んでいるときは、②の各段に「読む順：」のえらぶ欄も出ます。
何も選ばなければカードで選んだ既定の順（例：うしろから）のままですが、
「この段だけ左→右で読ませたい」のように、**段ごとに違う読む順**を指定できます。

### 答えの文字は、道の上でも かたまらないようにします

伊神さんの指摘：
> 赤文字「わかる」の三文字が連続して配置されてしまった。
> カモフラやほかの色が「わかる」の中に入らないと、迷路を解かなくても答えが分かってしまう。

**3つの決めごとで防いでいます。**

| 決めごと | なぜ |
|---|---|
| 目あての位置は「**道のどのあたりか**」で決める | 前は「空きマスの何番めか」だった。空きマスが少なくてかたまっていると、そのかたまりの中に均等にならべることになり、道の上では となり合った3マスに答えが並んでしまう |
| 道を3つに分け、重み **2 : 3 : 3** で配る（はじめは少なめ） | STARTのすぐそばに答えがあると、道をたどらなくても目に入る。3文字なら 1・1・1、5文字なら 1・2・2 |
| 答えの文字どうしのあいだは、**必ず1マス以上うめる** | すきまが1マスでも、そこが空白だと「わ□か□る」と読めてしまう。こさの設定に関係なく、そこだけは先に埋める（`mustFill`） |

置ける組み合わせは「広いほう」から探すので、実測では となり合う答え文字の
**9割以上が3マス以上**あきました（181組のうち、すきま2マスは9組だけ）。
すきま1マス（となり合わせ）は決まりで認めていないので、そもそも起こりません。

### 同じ色の段どうしは、文字が盤面の上でくっつかないようにします

STARTやGOALが変わっても同じ色で読み直す段では、**その段の文字どうし・前後の段の文字とも、
盤面の上でとなり合わせ（斜めも含む）にはしません**。伊神さんの指摘：
「ルート上だけ文字が多い」「答えの文字が連続して固まる」を、しかけを重ねたときにも守ります。

道がせまくて離して置けないときは、**わき道（迂回路）を足して使えるマスを増やしてから**
置き直します。それでも足りなければ、**盤面を少し大きくして作り直します**
（大きさは自動で決めます。STARTGOAL変更を2回以上重ねるような欲張った組み合わせほど、
作成に時間がかかることがあります）。

### 「線を消す」段が2つ以上あるときは、線の色をぜったいに使い回しません

★紙のとおりに解けるかどうかに直結する決めごとです。★

STEPは「この段で決めた4本」を key で名指しして消しますが、
問題用紙の指示は「**あかい**せんをけせ」と**色で**言います。
だから同じ色の線が盤面に他にもあると、解く人はそれも消してしまいます。

実測（直す前）：`✂️ → 🌟 → ✂️` の組み合わせだと段の色が **赤・青・赤・青** になり、
2つの「線を消す」段が**どちらも赤**。盤面には赤い線が8本立つのに STEPは4本しか消さないので、
**6回作って6回とも**、紙のとおりに解くと途中の段が読めなくなっていました
（`validateAll` は key で解くので「✓ すべてOK」と出て、検証をすり抜けます）。

いまは2重に防いでいます。

1. `stageColors()` が、線を消す段の色を**すでに使った色を飛ばして**割りあてる
   （`✂️✂️✂️` なら 赤・青・黄）
2. `makeOne()` の最後に「その色の線で、この段の key に入っていないものが1本でもあれば作り直す」
   （②の「色：」欄で手で同じ色にしたときも、ここで止まって理由が出ます）

検証は「**色で消したときも、STEPどおりの読みと一致するか**」を直接見ています
（`asPaper()` で keys を外して色だけで解き直し、段ごとの読みを突き合わせる）。

### 「線を消して次の段へ」は、こちらから「遠回り」を作ります

伊神さんの要望：
> 「線を消す」は必ずルートが変わるようにして。もともとのルートでは赤い線があることによって
> 進めず、遠回りしている。しかし、線を消すことによってもっと短いルートが見つかるため、
> 拾う文字が変わるということ。線を消すを選んだ時点で、もともとのルートが遠回りするように
> 壁を追加するなどして、「必ず」線を消す前と後で最短ルートが変わるようにしてほしい。

前の版は「**いまの迷路の中から、消すと近道になる壁をさがす**」やり方でした。
見つかるかどうかが運まかせで、見つかっても「角を1つ切るだけ」で道がほとんど変わらないことがありました。

いまは**逆に、こちらから作ります**。

| 手順 | すること |
|---|---|
| ① | いまの道から、みじかい区間（2〜7マス）をえらぶ |
| ② | その区間のまん中に**壁を1本足して、赤くぬる** ← これが「消す線」 |
| ③ | 足した壁のせいで行き止まりになるなら、先に**4マス以上長いまわり道をひらく** |

こうすると、さがす前から

- **消す前** … 赤い線でふさがれているので、遠回りするしかない
- **消したあと** … 区間が通れるようになり、みじかい別の道になる

が決まっています。②だけで足りることが多く（わき道のある迷路では、壁を1本足すだけで遠回りになる）、
一本道の迷路のときだけ③のまわり道を掘ります。

採用するのは、次を全部みたすものだけです。

| 条件 | 意味 |
|---|---|
| 道が4マス以上みじかくなる | 「消したら近道になった」と見て分かる |
| 前の道に無いマスを**3つ以上**通る | ただの近道カットではなく、**別の道**になる |
| 消す前も消したあとも1本だけ・差4マス以上 | どちらの段も「最短はこっちだ」と迷わない |
| 次の段の文字が置ける長さが残る | 短くなりすぎて文字が置けない、を先に落とす |
| **前の段の道が変わっていない** | 足した壁は盤面の最初からあるので、前の段にも効いてしまう |

最後の1つが要ります。足した壁は「線を消す段」だけに効くのではなく、**盤面の最初から立っている**ので、
前の段の道まで変えてしまうことがあります。段ごとの盤面のひかえを持っておいて、
前の段の道がぜんぶそのままかを毎回たしかめます。

とくに「線を消す」段が2つあるときは、2つめで足した壁が **1つめの効き目を消してしまう**
ことがありました（実測で「消しても道が0マスしか変わらない」が出た）。
そこで、作りおわったあとに**すべての「線を消す」段について**
「4マス以上みじかい・新しいマスを3つ以上通る」を数え直し、
1つでも欠けたら迷路ごと作り直します。

どうしても作れないときは「線を消しても道がじゅうぶんに変わりません」と理由を出し、
「わき道を増やす」「線を消す段を1つ減らす」「迷路を大きくする」を案内します。

## 迷路の画面は、100%表示では動きません

伊神さんの指摘：
> 迷路の画面は基本100%の全体表示です。その場合は迷路上でスクロールできないようにして。
> ズームインしているときもスクロールの上限を付けて。100%表示でもスクロールが効いているので、
> ページをスクロールするときに邪魔になったり、迷路が行方不明になってしまう。

3つの決めごとで直しました。

| 状態 | 動き |
|---|---|
| ぜんたいが見えている（100%） | 迷路は**まん中に固定**。指でもホイールでも動かない |
| ぜんたいが見えている＋ホイール | 迷路をつかまえず、**ページのほうがスクロール**する |
| ズームインしている | 動かせるが、**盤のはしが画面のはしより内側に入らない**ところで止まる |

ズーム中でも、はしまで来て1ドットも動けなくなったらページのスクロールにゆずります。
また、盤のまわりの余白を指でなぞったときは、100%表示ならページを縦に動かします
（キャンバスは `touch-action: none` なので、こちらで動かさないと iPad で
迷路の上をなぞってもページがスクロールできません）。

しくみは `editor.js` の `clampView()` 1つだけで、`draw()` の最初に必ず通します。
拡大・縮小・ドラッグ・ピンチ・ホイール・画面サイズの変更と入口がたくさんあるので、
「動かすたびにおさめる」ではなく「**描くたびにおさめる**」ほうが取りこぼしません。

## 答えは段ごとに切りかえて見られます

作ったあと、**1つの迷路の上で**「問題 ／ 1段めの答え ／ 2段めの答え …」をタブで切りかえられます。
段ごとに画面を並べるのではなく、同じ迷路に通り道だけを差しかえて見せます。

タブは編集のたびに作り直されるので、**手で直して段が増えれば、その場でタブも増えます**。
5 のSTEP一覧からSTEPを1つ選んだときは、どのタブにも当てはまらないので、どのタブも光りません
（そのときは 4 の盤面に「STEP◯ のあとの盤面（見るだけ）」と出ます）。

## 大きさの上限は1か所だけで決めます

`packages.js` の `MIN_SIZE = 6, MAX_SIZE = 20` が唯一の決めごとで、
`MZ.opt.RANGE` と HTML の `min/max` もこれに合わせています。

前は入力欄が 4〜30、`build()` が 6〜20 でクランプしていたので、
「迷路を **24×24** 以上にしてください」と案内しておきながら、そのとおりにしても
20×20 に丸められて永久に通らない、という状態でした。

## 段ごとに必要なマス数は、うしろの段から逆算します

「色でしぼる → スタゴル変更 → 線を消す → 色でしぼる」のような4段の組み合わせが、
18×18でもほとんど作れなかった原因はここでした。

前は「**次の1段ぶん**」しか見ていなかったので、

- 線を消す段は道が短くなるのに、その ぶんを前の段に足していなかった
- その先にもう1段あっても、そこまでは見ていなかった

ため、スタゴル変更のところで「次の段の文字が置ける長さ」だけを見てぎりぎりの短い道を作り、
そのあと線を消して短くなると**もう文字が置けない**、という行きづまり方をしていました。

いまは `stageNeeds()` が、うしろの段から次のように積み上げます。

| つなぎ方 | その段の道に要るマス数 |
|---|---|
| 読み直す（next-read） | 同じ道に2段ぶんの文字がのる → 足し算 |
| 線を消す（erase-wall） | 次の道はこの道より最低4マス短い → その ぶん長く |
| START/GOALが変わる | まったく別の道なので、長さは引き継がない |

あわせて「**あとの段の文字のうち、この段の道の上にも乗るもの**」も数に入れます。
文字はうしろの段から先に置くので、その ぶんのマスはもうふさがっているからです。

また「前の道と重ならない、正味の新しいマス」は、道ぜんたいの長さより**多め**に要ります
（つながった道なら1マスおきに置けますが、前の道を除いた残りはあちこちに散らばるため）。
`spacingNeed`（文字数×1.6＋2）と `spreadNeed`（文字数×2.4＋2）を使い分けています。

## 手で壁を作ったあと、今の最短ルートをその場で見られます

伊神さんの要望：
> 自筆ルートが最短になるように壁を作るのは自動でできるが、
> 手動で壁を作ったときに最短ルートはどれかを表示できるボタンを追加してほしい。

盤面の上のツールバーに **「🔎 最短ルート」** を置きました。

- 押すと、いまの壁でのSTART→GOALのいちばん短い道が**青い線**で出ます
- 下に **「最短ルート：14マス／同じ長さの道が 3通りあります」** と出ます
  （1本だけなら「1本だけです」）
- **押したまま壁を足したり消したりすると、そのつど引き直されます**
- もう一度押すと消えます。「ルート」道具を選ぶと、じゃまなので自動で切れます

以前は「B 正解ルート」パネルの奥にチェックとして入っていましたが、
壁を直しながら見るには遠かったので、盤面のすぐ上に出しました。
**設定は `A.showShortest` の1か所だけ**に持っています
（同じ意味の設定を2か所に持つと、片方だけ直して食いちがうため）。

## 「最短ルートが複数あります」は、その場で直せます

手で壁を消したり「外わくだけ」にしたりすると、STARTからGOALへの最短ルートが
何通りもできてしまうことがあります。前はチェックに ⚠ が出るだけで、
**どの壁を足せば1本になるのかは人には分かりませんでした**（伊神さんの指摘）。

いまは、その警告のところに **「🔧 わき道をふさいで1本にする」** ボタンが出ます。

考え方はかんたんです。

1. STARTからの距離 `dS` と GOALからの距離 `dG` を1回ずつ測る
2. 「最短ルートのどれかが通る辺」は `dS[a] + 1 + dG[b] === 最短の長さ` で見分けられる
3. そのうち **残したい道の上にない辺だけ** を壁でふさぐ

壁を足すだけなので、残したい道は短くならないし、通れなくもなりません。
残る最短ルートは その道1本だけになります（実測：8×8 の「外わくだけ」で 3432通り → 1通り）。

一方通行やワープがあるときは「行き」と「帰り」で距離が変わるので、
このやり方は使えません。そのときは理由を出して断ります。
残したい道がそもそも最短でないときも、
「先に『このルートが最短になる迷路を作る』を使ってください」と案内します。

## 「最短はこっちだ」と迷わせないしくみ

伊神さんから「最短なのかどうか怪しい距離感だった」という指摘を受けて入れた、いちばん大事な部分です。

**既定では、ぐるっと回れる道（輪っか）を作りません。** 道は木の枝のように分かれるだけなので、
STARTからGOALへの行き方は**そもそも1通りしかありません**。行き止まりに入ったら戻るだけです。

わき道（輪っか）を足す設定にしたときは、**次に短い道との差を必ず4マス以上**にします。
この差は「2番目に短い一本道」をきちんと計算して出しています（ヤンの方法の考え方）。
「1歩よそへ出て戻る」ような歩き方は別の道として数えないので、見た目どおりの差が出ます。

画面には「ほかに行ける道がないので、まちがえようがありません」「次に短い道より 6マス 短い」
のように出るので、印刷する前に確かめられます。

## まぎれ文字（カモフラージュ）の考え方

伊神さんから「答えのルートだけ文字が多い」「まぎれ文字が答えに似た字ばかり」という指摘を受けて直しました。

- **ルートの中の文字の詰まり具合は、まわりと同じ「こさ」**にします。
  以前はルートの空きマスを必ず100%埋めていたので、まわり（こさ設定ぶんしか埋めない）と比べて
  答えのルートだけ文字がびっしり詰まって見え、そこだけ目立ってしまっていました。
- **まぎれ文字は、まずひらがな46字すべてを土台にします。**
  以前は「答えで使われている字」だけを材料にしていたので、字の種類が4〜8個しかないときは
  まぎれ文字が答えとそっくりな字ばかりになっていました（漢字・カタカナ・数字の答えのときは、
  その字も少しだけ混ぜて種類がゼロにならないようにします）。
- **答えの文字どうしも、盤面の上でくっついて見えないようにします。**
  道の「通った順」だけで均等に置くと、道が折り返しているところでは文字どうしが
  紙の上ではすぐ隣に来てしまうことがありました。盤面のマス目のあらさで
  離れ具合を測り、いちばん離れて置ける距離を探してから並べています。

## 出力

- **印刷**：問題用紙（やることの文＋迷路）／段階ごとの盤面／答え
- **白黒印刷**：色を「線のもよう＋文字の飾り」に置きかえ、凡例もつけます
- **PNG保存**：印刷と同じ大きさで書き出します

画面・印刷・PNG・プレイヤー画面は**同じ描画関数を1本だけ**通しています。

### 画像に全体の指示文を入れる

5 の「E 印刷・保存・書き出し」にある**問題用紙・画像にのせる文**の欄を直すと、
**印刷にも画像にも 4 の表示にも**同じ文が出ます（前は「印刷は自動生成の文・画像は欄の文」と
2系統あり、欄を直しても紙には効きませんでした）。「🖼 画像にもこの文を入れる」がONだと、
**PNG画像の迷路の上に、全体の指示文が1行で入ります**。印刷はもともと問題用紙に文章として
刷っていましたが、PNG画像だけを配る・SNSに貼るときなどは絵の中に文字が無いと意味が伝わらないため、
画像そのものに焼きこめるようにしました。

- **既定は自動作成の指示文をそのまま1行で**入れます。文章が長くて1行に収まらないときは、
  読める最小の大きさ（11px）まで自動で縮め、それでも収まらなければ**その大きさのまま自動で複数行に折り返し**ます
  （無理に1行へ押しこんで読めなくすることはありません）。
- **自分で改行を打って書きかえると、その行どおりに複数行で出ます**（自動の折り返しはしません＝手で入れた改行を優先します）。
- 欄は自動作成の指示文と同期しますが、**自分で書きかえた内容は、迷路そのものを作り直すまで消えません**。

### スマホでは「写真に保存」も選べます

ファイルのダウンロードだと、スマホでは写真アプリからすぐに見つけにくいことがあります。
端末がWeb Share APIの「ファイル共有」に対応しているとき（多くのスマホのブラウザ）だけ、
「📱 写真に保存」ボタンが出ます。押すとOSの共有シートが開き、そこから「画像を保存」を選ぶと
写真フォルダへ直接置けます。対応していない端末・PCではボタンごと出ません（ダウンロードのみでよいため）。

## くわしく直したいとき（5 もっと細かく直す）

**画面は切りかわりません。**ふだんの直し（文字・記号・かべを置く／動かす／色を変える／消す）は
**4 の盤面で完結します**。5 はそれ以外——STEPの並べかえ、チェック、印刷設定、
「読み方とこたえ」でまとめて置き直す、といった機能の置き場です。

5 の中の見出しは **A〜F** です（ページの見出しは 1〜5）。
前は 5 の中も ①〜⑥ だったので「⑤の①」のような言い方になり、どこの話か分かりませんでした。

| | 中身 | 既定 |
|---|---|---|
| A | 盤面と文字の量（いまの盤面を作り直す「変える」もここ） | 閉 |
| B | 正解ルート（自分で道を描くとき） | 閉 |
| C | 読み方とこたえ（ねらった答えになるように置き直す） | 閉 |
| D | チェック（謎として成立しているか） | **開** |
| E | 印刷・保存・書き出し（問題用紙にのせる文もここ） | 閉 |
| F | こまかい設定（自動作成では使いません） | 閉 |

5 のボタンを押すと盤面が変わりますが、そのとき盤面が画面の外にいると変化が見えません。
**見えていないときだけ 4 の盤面まで自動で戻します**（見えているときは動かしません）。

### 読み方とこたえ（5 の C）

**自動で作ると、5 の C にはかんたん作成で作った
段ごとの「読むルート・色・読む順・こたえ」がすでに入っています。**
空のまま渡していたので何を直せばいいか分からなくなっていた問題を直しました。
中身を書きかえれば、そのままそこだけ直せます。

**「このルートを、この色で、この順に読んだら、この言葉になる」を並べて書くと、
全部が同時に成り立つように文字を置き直します。**

```
1行め： STEP1（最短ルート）      ／ 赤だけ ／ 通った順   ／ あかいせんけせ
2行め： STEP5（線を消したあと）  ／ 青だけ ／ 左 → 右    ／ あおじみぎから
                                   ↓
                    [ ✨ この通りに置く ]
```

置いたあとに読み直して、`✓ 1行め：「あかいせんけせ」` のように結果を見せます。
**こたえの欄を空にしておけば「いま何が読めるか」を見るだけ**にも使えます
（以前の「読み取りのお試し」はここに一本化しました）。

**まぎれ文字は「その行が読まない色」でしかまきません。**
たとえば「黒だけ読む」行があるときは黒のまぎれ文字を置かず、赤でまきます。
（第4弾までは読む色と同じ色でまいてしまい、こたえに関係ない文字がまざっていました）

同じ色を読む行どうしでルートが重なっていると、どう置いても両立しないので、
**置く前に理由をつけて止めます**（「どちらかの読む色を変えてください」）。

**読むルートには、STEPの通り道だけでなく「自分で描いたルート」も選べます。**
5 の B で「＋」を押すとルートを何本でも持てるので、
`ルート1に①の答え／ルート2に②③の答え` のような置き方ができます。

### ルートを遠回りにする（5 の B）

**「🔀 ルートを遠回りにする」**を押すと、いまの最短ルートだけを長くします。

```
【使う場面】 1段め・2段めまで作ったあと、3段めで「もっと短い道」を作りたい。
             でも今の道がギリギリ短くて、壁を消しても近道の余地がない。
```

**置いてある文字の並び順も、いまのSTEPの答えも変わりません。**
遠回りする区間の文字はいっしょに運ばれ、チェックが悪くなる案は採用されません。

| 分類 | 内容 |
|---|---|
| 迷路編集 | 大きさ変更・壁の追加/削除・START/GOAL（複数可）・Undo/Redo・ズーム/パン |
| 正解ルート | ペンで描く／途中から描き直す／長さ表示／**このルートが最短になる迷路を作る** |
| 情報配置 | ひらがな・カタカナ・漢字・英字・数字・記号／色6色／大きさ／ドラッグ移動・複製・範囲選択 |
| 自動配置 | 読み方とこたえ（ねらった答えにする）／読む順に合わせた配置／まぎれ文字の自動散布 |
| 抽出 | 通過文字・色フィルター・読み順6種・奇数/偶数番目・種類しぼり |
| ギミック | ○を通る／×を避ける／一方通行／START変更／GOAL変更／線を消す／文字を消す／反転・回転／ワープ |
| 連鎖 | STEPエディタ・状態変化・再探索・ルート形状取得・別盤面への転写・囲まれた領域 |
| 検証 | 到達可能／最短が1本か／次に短い道との差／**同じ通路を2回通らないか**／○全通過／×回避／STEP間の状態変化／想定こたえとの一致 |

### 操作のこつ

| やりたいこと | やり方 |
|---|---|
| 迷路の変更をもどす | Ctrl+Z（4 のツールバー右がわの「↶」） |
| STEPの変更をもどす | 5 のSTEP欄の「↶ STEPをもどす」（迷路とは別の履歴です） |
| いまの盤面をその大きさに作り直す | 5 の A の「変える」（②の たて/よこ は「次に作る迷路」の設定） |

## ファイル構成

```
meiro-nazo-maker/
├── index.html   画面とスタイル
└── js/
    ├── model.js     データ構造（Maze / Wall / Element / Route / Start / Goal）
    ├── engine.js    最短経路・道の本数・次に短い道との差・一方通行・○×・ワープ
    ├── generate.js  正解ルート → 迷路の自動生成
    ├── render.js    描画（画面・印刷・PNG・プレイヤー画面で共通の1関数）
    ├── ops.js       ギミック部品のレジストリ（入力→処理→出力）＋抽出
    ├── steps.js     STEPの連鎖・State計算・自動検証
    ├── opt.js       ②と⑤で共通の設定（大きさ・文字の量・わき道）
    ├── packages.js  しかけ9つ。条件を満たす迷路が出るまで作り直す
    ├── wizard.js    1〜4の配線（しかけ選び・文章・作る・段の切りかえタブ）
    ├── editor.js    キャンバス操作・Undo/Redo・ズーム/パン・その場文字入力
    └── app.js       盤面とSTEP・こまかい設定（5）の配線
```

### 設計上の約束（次に触るときのために）

- **設計図（Maze）と、STEPを通したあとの盤面（State）を分ける。**
  STEPを走らせるときは毎回 Maze を複製してから変換をかけるので、STEPをいじっても設計図は壊れない。
- **描画関数は `MZ.render.drawBoard` の1本だけ。** 画面・印刷・PNG・プレイヤー画面は全部これを呼ぶ。
- **ギミックは `MZ.ops.register()` に1つ足すだけで増える。** if文の場合分けは作らない。
- **謎の型は `MZ.packages.register()` に1つ足すだけで増える。**
  `make(recipe)` の中で作って、`MZ.steps.validateAll` に通し、**警告が1つでも出たら捨てて作り直す**。
  だから出てくるものは必ず解ける。
- 道は「ぐねぐね曲がった一本道を先に描く → その道が最短になる迷路を作る」順で作る。
  先に迷路を作ると、文字を置く場所も近道になる壁も足りなくなる（実測で197/200が失敗した）。
- **同じ意味の設定は1つしか持たない。** 画面の入力欄は `MZ.opt` の値を映すだけ（`opt.js`）。
  同じものが2か所にあると「どちらが効いているのか」が分からなくなる。
- **ルートの上にまく文字は、その段で「読まれない色」でなければならない。**
  読む色でまくと、こたえに関係ない文字がまざる。`answerColor()` と `noiseColor()` で必ず対にして決める。
- **読む順を変える謎は、置くときにも同じ並べかえを通す。**
  `placeOnFree()` が `MZ.ops.applyOrder` を呼ぶので、読み方と置き方がずれない。
- **まぎれ文字の「こさ」は、盤面のどこでも同じにする。**
  ルートの中だけ・外だけで別の埋め方をすると、密度の差でルートが目立ってしまう。
  `curDensity()` を通して同じ「こさ設定」を使う。
- **まぎれ文字の材料は、答えの字ではなく広い字の集まりから選ぶ。**
  答えの字だけを材料にすると、種類が少ないぶん答えと同じ字ばかりになる。
  `poolFrom()` はひらがな46字を土台にし、答えの字は足りない種類を補う程度に混ぜるだけにする。
- **段の色は「読み直す＝次の色／線を消す・スタゴル＝赤にもどす」（`nextAutoColor()`）。**
  これは伊神さんが決めたルールで、勝手に変えない。
  段の色は「文字が何色か」だけでなく「**その段の文字を置けない場所**」も決めるので、
  `stageColors()` が**そのままでは謎が成り立たない2つの場合だけ**色をずらす。
  ① 「線を消す」段どうしが同じ色（紙の指示が色なので、ほかの段の線まで消える）。
  ② 赤にもどした先に、**道がほとんど同じ前の赤い段**がある（置き場所が消える）。
  `move-start`／`move-goal`／`move-both` は前の道と重ならない道を選ぶので、
  そこをまたいだら赤にもどせる（`usedHere` をまっさらにする）。
  ずらした段は `stageColors()` の返り値に `.forced` として残り、②の画面が理由を出す。
  `opts.stageColor[段番号]` を渡すと、その段だけ指定した色を使う
  （かんたん作成②の「色：」欄。ただし ① だけは、正しさのため必ず直す）。
- **同じ色を使う段どうしは、前の段の道と重ならないマスに文字を置く。**
  STARTやGOALが変わっても新しい道はたいてい前の道の一部を通るので、
  重なるマスに文字を置くと前の段を歩いたときに次の段の文字まで見えてしまう。
  `placeOnFree()` の `avoidSet` で、同じ色を使っている段の道をすべて除外する
  （`sameColorBefore()`／`sameColorAfter()`。個別に色を上書きできるので、既定のときのように
  連続している前提をおかず、連続していなくても同じ色の段を漏れなく拾う）。
- **読む順も段ごとに上書きできる。**
  `readOrder(parts, opts, 段番号)` は `opts.stageOrder[段番号]` があればカードの既定より
  それを優先する。文字の置き方（`placeOnFree` に渡す並べ順）と抽出後の並べかえSTEPの
  両方に同じ値を使うので、置き方と読み方がずれない。
- **文字は「同じ道の中」だけでなく「別の段の文字」ともくっつけない。**
  同じ色の前後の段は道こそ避けているが、盤面の上ではすぐ近くを通ることがある。
  `placeOnFree()` の `extraNear` に、すでに置いた段の文字の位置を渡し、
  そこからも一定の距離（D）を離す。
- **文字を置く順番は「きつい段」から。**
  道の長さではなく「その段が実際に使えるマス（ほかの同じ色の段の道を除いたもの）」が
  文字数に対してどれだけ余っているかで決め、余りの少ない段から先に置く。
  うしろの段から順に置いていたころは、いちばんきつい段——たとえば前の段と同じ色で、
  道がその前の段と重なっている段——の番になったときにはもう空きが残っておらず、
  作れないことがとても多かった。
- **置き場所さがしは、行きづまったら1つ前にもどってやり直す。**
  ぐねぐね曲がった道だと、道すじの上では離れているマスが盤の上ではとなり合う。
  1文字ずつ「いちばん目あてに近いマス」を取っていくだけだと、そこで先がふさがり、
  実際には置ける組み合わせがあるのに「置けない」と投げ出していた。
  `tryFit()` は目あてに近い順に試しつつ、深さ優先で後戻りする（探索の上限つき）。
- **盤面を変える処理は、前の段の道が変わっていないかを必ず確かめる（`earlierRoutesKept()`）。**
  「線を消す」段は壁を足し、「STARTやGOALが変わる」段は遠回りを作るために迷路を組み直す
  （`rewireAsTree`）。どちらも盤面ぜんたいを変えるので、前の段の道まで変わる。
  段ごとに「解いたときの条件」（そのとき無効だった壁・START・GOAL）だけ覚えておき、
  いまの盤面で解き直して照合する。★**確かめる範囲は `i + 1` まで**★ ——
  その段の道（`routes[i]`）は、その段の変換が出発点にしているので、いっしょに守る必要がある。
  `i` までにしていたころは「1段めの読みがちがう（`read:0`）」で作り直しになるのが
  行きづまりの半分を占めていた（4段スタゴル＋線けしで 7/8・9.0秒 → **8/8・1.9秒**）。
- **同じ色にもどせるのは「線を消す」を2回はさんだあと（`ERASE_TO_REUSE = 2`）。**
  同じ色の2段は、おたがいに「自分だけが通るマス」を持たなければならない。
  線を消す1回ぶんの分け方（実測で3マス）では足りず、2回ぶんなら足りる
  （赤→赤は 2/8、赤→青→赤は 7〜8/8）。`move-*` は道がまるごと別物になるので1回でよい。
  分ける大きさの限界も測ってある：7〜8マスまでは 8/8、11〜12マスで 5/8、14マスで 1〜5/8。
- **道の長さは「必要なぶん＋2割」でおさえる（`randomPath()` の `maxCells`）。**
  上限が無いと、遠くまで行ってから帰ってくるぶんで必要の2〜2.7倍になる。
  上限は「いまの長さ」ではなく「**いま まっすぐ帰ったら何マスになるか**」で見る
  （いまの長さで見ると、帰り道ぶんそのまま超える）。
  足りないときは `build()` が1割ずつのばして作り直すが、**のばすのは
  `place:`／`read:`（置き場所が足りない）で行きづまったときだけ**（`roomShort()`）。
  START/GOALの置き場所が見つからない系ではのばしても効かず、1回が重くなるだけ。
- **「線を消す」段は、さがすのではなく作る（`forceDetour()`）。**
  いまの道の上に壁を1本足して赤くぬれば、その線が近道をふさいでいる状態が最初から作れる。
  行き止まりになるときだけ、先に4マス以上長いまわり道をひらく。
  ★足した壁は盤面の最初から立っているので、**前の段の道にも効く**。
  段ごとの盤面のひかえ（`boards[]`）で前の段の道が変わっていないか毎回たしかめ、
  さらに作りおわったあとに、すべての線けし段の効き目（4マス以上・新しいマス3つ以上）を
  数え直す。1つでも欠けたら迷路ごと作り直す。
- **段ごとに要るマス数は、うしろの段から逆算する（`stageNeeds()`）。**
  「次の1段ぶん」しか見ないと、線を消して道が短くなる ぶんも、その先の段のことも
  織りこめない。読み直す＝足し算、線を消す＝最低4マスぶん長く、START/GOAL変更＝引き継がない。
  「あとの段の文字のうち、この段の道の上にも乗るもの」も数に入れる。
- **「道ぜんたいの長さ」と「前の道と重ならない正味のマス」は、必要量がちがう。**
  つながった道なら1マスおきに置けば距離2を守れるが、前の道を除いた残りはあちこちに
  散らばるので、同じマス数でも離して置ける組み合わせが見つかりにくい。
  `spacingNeed`（×1.6＋2）と `spreadNeed`（×2.4＋2）を使い分ける。
- **総あたりで探すときは、先に1回だけ距離をひろげてふるい分ける（`distFrom`/`tooShort`）。**
  START/GOALの置き場所を1か所ずつ解いていると、18×18の1つの段で最大900回も探索が走り、
  4段の組み合わせは作るのに30秒以上かかっていた。START側から1回ひろげておけば
  「そもそも短すぎる置き場所」は解かずに落とせる（実測で 33秒 → 1.3秒）。
  一方通行があると行きと帰りで距離が変わるので、そのときはふるい分けを使わない。
- **段が多い組み合わせは、同じ大きさでねばるより早く盤を広げる。**
  `build()` は3段以上のとき、最初の大きさでの試行回数を半分にしてから `grows` で広げる。
- **文字どうしの間隔（D）は2以上を必ず守り、足りなければ道を伸ばしてから作り直す。**
  以前はD=1（隣どうし）まで許していたので、まれに答えの文字がくっついて見えることがあった。
  `placeOnFree()` はD≧2で置けないと失敗を返し、STARTGOAL変更の直後は
  `tryLengthenForRoom()` が `generate.lengthenRoute()` で道を迂回させてマスを増やしてから
  もう一度試す。それでも足りなければ `build()` が盤面を少し大きくして作り直す（`grows`）。
- **最終こたえだけでなく、段ごとの読みも1つずつ確かめる。**
  盤面が変わるたびに `chars`/`text` はリセットされるので、最後のこたえが合っていても
  途中の段の読みが別の段の文字とまざっていることに気づけない。`makeOne()` は
  各段の読み終わり地点（checkpoint）の `text` を、その段のねらいの文章と1つずつ照合する。
- **文字の置き場所は「置けるか」でふるいにかけ、盤面のあらさで距離を測って選ぶ。**
  出せるいちばん大きい隣接距離をさがし、その距離を保てる範囲でいちばん均等に近いマスを選ぶ
  （`placeOnFree()`）。欲張って手前から詰めると、後半の文字が逃げ場を失って固まる。
- 外部ライブラリ・CDNなし。`file://` で直接開いても動く。
- **「大きさを決める（measure）」と「実際に描く（drawBoard）」は、かならず同じ計算結果を使う。**
  指示文のように大きさが動的に決まるものを別々に計算すると、確保した余白と実際に描く
  内容がずれて、はみ出したり余白が余ったりする。`render.js` の `fitInst()` を両方から
  呼び、`measure()` の戻り値に `instLines`/`instFontSize` として結果を持たせている。
- **同じ意味の値は1か所でしか決めない（大きさの上限・指示文）。**
  上限は `packages.MIN_SIZE/MAX_SIZE` が唯一の決めごとで、`MZ.opt.RANGE` と HTML の
  `min/max` はそれに合わせる。指示文は `maze.meta.instruction` ひとつで、
  欄を直したら `applyInstEdit()` がそこへ書きもどす（印刷・画像・4の表示が同じ文を見る）。
- **設定を画面に入れるときは、DOMに直接代入しない。**
  `MZ.opt.bind` は `change` しか見ないので、`$('#inRows').value = …` では中の値が変わらない。
  必ず `MZ.opt.set()` を通す。通さないと「欄は12なのに中身は8」の状態になり、
  そのまま作り直すと作品が切り縮められる。
- **色で指す指示（「あかいせんをけせ」）は、その色のものが他に無いことまで確かめる。**
  STEPは key で名指しできるが、紙の上の人は色でしか見分けられない。
  `stageColors()` が色を使い回さないようにし、`makeOne()` の最後にも
  「その色で key に入っていないものが無いか」を確かめる。
- **「見せるための絵」と「編集するための盤面」を二重に持たない。**
  4 に出るのは `#board`（編集そのもののcanvas）で、段の切りかえは
  `A.selStep` を動かして `ED.setDisplay()` するだけ。結果をPNGで見せていたころは、
  絵と編集用の盤面が別々にあり、直すには下の別の盤面まで行く必要があった。
  タブは `MZ.app.stageInfo()` を `refresh()` のたびに読み直して作るので、
  手で直して段が増減しても、こたえが変わっても、その場で追いかけて変わる。
- **CSSで高さを決めるときは、中身の行数で変わる部分を巻きこまない。**
  盤面の高さは箱（`.pane-canvas`）ではなく「迷路が映る部分」（`.canvas-wrap`）に
  直接かける。ツールバーの行数は画面の幅で変わるので、箱の高さを決める方式だと
  せまい画面でツールバーが3行になったぶん迷路だけがつぶれて豆つぶになる。
- **モードを切りかえるときは、前のモードが残した表示指定を消す。**
  `updateRouteView()` は「見るだけのときは何もしないで戻る」ので、
  `routePaths` や `routeColor` は前の値が持ち越される。
  `editor.draw()` の `S.display` 分岐で、使わないものを明示的に `null`／`undefined` に戻す。
- **広い try/catch は、直したつもりの不具合を「作れませんでした」に化けさせる。**
  `build()` の catch は回数と最初のメッセージを `diag` に残し、
  それがいちばん多ければ「道具のほうの不具合です」と正直に出す。
  （実際に、変数名の付けかえ漏れによる TypeError が「作れず」に化けて1度見逃しかけた）
- **離れた場所のボタンが盤面を変えるときは、盤面が見えているか確かめてから実行する。**
  5 のボタンは 4 の盤面を変える。`afterEdit()` の最後で `revealBoard()` を呼び、
  盤面が画面の外にあるときだけスクロールして戻す（見えているときは動かさない）。
  同じ理由で「↶ 迷路をもどす／↷ すすむ」は 4 のツールバーに置いてある。
- **自動作成の結果を編集エリアに渡すときは、STEPを唯一の元データとして③を組み立てる。**
  `deriveTargetsFromSteps()` は `A.results`（STEPを走らせた結果）から段ごとの
  読むルート・色・読む順・こたえを読みとる。②と同じで「別のデータ構造を並行して持たない」。
- **STEP由来の読み取り確認は、そのSTEP時点の盤面で行う。**
  多段の謎は前の段の文字を隠してから次の段を解くので、確認用の `readRow()` を
  常に最新の `A.maze` で行うと、まだ隠れていない前の段の文字まで拾ってしまう。
  `routeSources()` はSTEPごとの盤面スナップショットも持たせ、`verifyTargets()` はそれを使う。
- **同じ役目の記号が2つ以上あるときは、記号そのものを変えて区別する。**
  `set-start`/`set-goal` のSTEPは「この記号・この色の要素をさがす」で新しいSTART/GOALを見つけるので、
  ★が2つあると先に置いた方を誤って拾う。STARTGOAL変更が2回め以降のときは
  `markerFor()` が★☆→■□→▲△→◆◇／●♪／↑→ と毎回ちがう記号を選ぶ。

## 動かない・困ったとき

- **作れませんでしたと出る**：文章が長すぎます。盤面を大きくするか、文章を短くしてください
- **作るのに時間がかかる**：段が3つ以上の組み合わせは、条件を全部みたす迷路が出るまで
  何度も作り直します（実測で数秒〜十数秒）。盤面は自動で少しずつ大きくします
- **保存できない**：プライベートモードでは保存できないことがあります。「ファイルに書き出す」を使ってください
- **文字が読めない**：白黒印刷なら「白黒で印刷する」にチェック
